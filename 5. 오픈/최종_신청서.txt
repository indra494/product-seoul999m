게임소개 :
독성 먼지로 지상이 폐쇄된 미래, 인류는 공기 정화층이 작동하는 지하 999m에 도시를 세웠다. 휴먼·버그본·AI 로봇의 영웅을 조작해 상대에게 보이지 않게 30초간 땅굴을 파고 광석과 진군로를 확보하라. 개전 후 자동 진군대와 고철 시설로 적의 길을 끊고 거점을 파괴하라. 캠페인·AI 대전·방 코드 1:1 온라인을 지원하는 실시간 전략 액션 게임.


Codex와 함께 게임을 만든 과정 선택
개발 과정에서 Codex를 활용한 부분이나 이로 구현한 기능, 해결한 문제와 개발자가 직접 개발 진행한 구분하여 설명해주세요.

서울 지하 999M은 아이디어 검토부터 기획·설계·개발·오픈까지 Codex와 지속적으로 협업해 만든 웹 전략 액션 게임입니다. 아이디어를 입력하고 완성된 게임을 한 번에 생성한 것이 아니라, 제가 게임의 방향과 재미를 결정하고 Codex와 대화하며 구현과 수정을 반복했습니다.

1. 아이디어 검토와 방향 설정
처음에는 “Codex로 어느 정도 수준의 게임까지 만들 수 있을까?”라는 생각에서 출발했습니다. 제가 생각해 둔 여러 게임 아이디어를 Codex로 간단하게 구현해 보면서 실제 개발 가능성과 재미를 확인했습니다. 짧은 기간 안에 완성하기 어렵거나 핵심 재미가 명확하지 않은 아이디어는 제외했습니다.
최종적으로 직접 땅굴을 파서 공격로를 만들고, 그 길로 부대를 보내 적 거점을 파괴한다는 아이디어를 선택했습니다. 땅굴을 직접 만드는 조작과 부대의 자동 전투를 결합하면 일반적인 전략 게임과 다른 경험을 만들 수 있다고 판단했습니다.

2. 기획과 설계 과정
게임의 핵심 전략과 규칙, 세계관, 캐릭터와 종족의 설정, 전체적인 분위기는 제가 먼저 구상했습니다. 이후 제가 생각한 내용을 Codex와 계속 이야기하며 실제 플레이가 가능한 규칙으로 구체화했습니다.
처음에는 땅굴을 파는 기능 자체에 집중했지만, 직접 플레이해 보니 땅굴을 오래 파는 과정과 전투를 기다리는 시간이 루즈하게 느껴졌습니다. 이를 개선하기 위해 준비 시간을 30초로 줄이고, 공격 경로를 만든 뒤 빠르게 전투로 넘어가도록 게임의 흐름을 변경했습니다.
전투 중에도 부대가 싸우는 모습을 지켜보기만 하지 않도록 A/B 공격 경로 선택, 다음 WAVE 병력 배분, 영웅 조작, 시설과 전술지원 등을 추가했습니다. 플레이어가 전투 중에도 계속 판단하고 개입할 수 있도록 하여 자동 전투의 장점은 유지하면서 지루함을 줄였습니다.
캐릭터, 맵과 유닛 디자인도 제가 원하는 콘셉트를 정하고 Codex와 시안을 주고받으며 발전시켰습니다. 그래픽 제작 경험이 많지 않아 현실적인 제작 범위를 고려해 도트 그래픽을 선택했고, 과장된 캐릭터 표현을 더해 각 캐릭터에 개성 있고 유쾌한 B급 감성을 담았습니다. 생성된 결과를 그대로 사용하지 않고 여러 시안을 비교하면서 게임 분위기에 맞도록 수정했습니다.

3. 프로젝트 구성과 Codex 활용 방식
프로젝트 초기부터 Codex와의 작업을 아이디어·기획·설계·개발·오픈의 다섯 단계로 구분했습니다. 코드를 만들기 전에 각 단계에서 무엇을 결정하고 어떤 결과물을 남길 것인지부터 정했습니다.
특히 기획, 설계와 개발 파트마다 Codex가 따라야 할 별도의 작업 지침을 미리 구성했습니다. 기획 단계에서는 게임의 핵심 재미와 규칙, 사용자 경험을 먼저 정리하고, 확정되지 않은 아이디어를 실제 기획과 구분하도록 했습니다. 설계 단계에서는 데이터 구조와 기능 간 관계, 온라인 처리 방식과 테스트 방향을 문서화한 뒤 구현하도록 했습니다. 개발 단계에서는 확정된 기획과 설계를 기준으로 코드를 수정하고, 기존 기능에 미치는 영향과 실제 브라우저 동작을 함께 확인하도록 했습니다.
프로젝트 전체의 확정 사항을 저장하는 프로젝트 메모리, 현재 진행 상황과 다음 작업을 기록하는 현재 작업 문서, 변경 및 문제 해결 과정을 남기는 Codex 활용 로그도 만들었습니다. 덕분에 대화가 길어져도 이미 폐기한 아이디어가 다시 적용되거나 기획과 실제 구현이 달라지는 문제를 줄일 수 있었습니다. 저는 필요한 기능과 원하는 경험을 설명했고, Codex는 문서와 기존 코드를 먼저 확인한 뒤 작업하도록 활용했습니다.

4. 개발과 문제 해결 과정
제가 구현된 게임을 직접 플레이하면서 굴착 속도, 전투 흐름, 난이도, 조작성과 화면의 정보량을 확인하고 문제점을 Codex에 전달했습니다. Codex는 문제가 발생하는 상황을 재현하고, 코드와 실행 결과를 분석해 원인을 찾은 뒤 수정안을 구현했습니다.
특히 플레이어가 자유롭게 만든 땅굴은 형태가 일정하지 않아 영웅과 부대가 목적지를 찾지 못하거나 엉뚱한 길로 이동하고 중간에 멈추는 문제가 발생했습니다. Codex와 함께 실제 이동 경로와 목표 선택 과정을 확인한 뒤, 막힌 목표를 제외하고 경로를 다시 계산하며 일정 시간 움직이지 못할 경우 새로운 경로를 찾는 복구 방식을 적용했습니다.
온라인에서는 참가자가 판 땅굴이 다시 벽으로 돌아가거나 서로 다른 길로 인식되는 문제도 있었습니다. 방장과 참가자의 동작을 동시에 확인하고 굴착 결과와 지형 정보를 동일하게 처리하도록 동기화 구조를 수정했습니다. 미니맵 위치가 어긋나는 문제와 모바일 UI가 게임 화면을 가리는 문제도 같은 방식으로 개선했습니다.

5. 제가 한 일과 Codex가 한 일
게임의 아이디어와 핵심 재미, 세계관, 전략 규칙, 캐릭터와 종족의 방향은 제가 정했습니다. 어떤 부분이 재미있거나 루즈한지, 어떤 기능을 추가하거나 제외할지 역시 제가 직접 플레이하며 판단했습니다. Codex가 제안한 결과도 그대로 채택하지 않고 여러 방향을 비교해 최종 결정을 내렸습니다.
Codex는 제가 정한 방향을 기능으로 구현하고, 프로젝트 문서를 관리하며, 반복적으로 발생하는 문제의 원인을 찾아 개선하는 역할을 했습니다. 저는 게임의 목표와 경험을 설계하고 결과를 평가했으며, Codex는 이를 빠르게 구현하고 검증했습니다. 이러한 협업을 통해 짧은 기간에도 제가 구상한 전략성과 개성을 유지하면서 실제로 플레이할 수 있는 게임을 완성할 수 있었습니다.
