# 서울 지하 999M 게임 개선 관리대장

## 문서 상태

- 상태: `상시 갱신 / 개선 백로그 기준 문서`
- 작성일: 2026-08-24
- 목적: 사용자와 Codex가 플레이 경험, 화면, 조작, 전투 전달력과 제출 완성도의 문제를 계속 발견하고 검증하며 개선하는 과정을 한곳에서 관리한다.
- 기준 기획: `2. 기획/서울지하999M-게임-기획-초안.md`
- 기준 설계: `3. 설계/서울지하999M-프로토타입-설계.md`
- 기준 구현: `4. 개발/seoul-999m-below/`

이 문서에 등록됐다는 사실만으로 문제 진단이나 개선안이 확정된 것은 아니다. 실제 플레이, 캡처, 사용자 피드백과 테스트로 확인한 뒤 사용자가 채택한 내용만 기준 기획·설계와 구현에 반영한다.

## 1. 관리 원칙

1. `문제`와 `개선안`을 분리한다. 같은 문제에도 여러 해결책이 있을 수 있다.
2. 느낌만으로 즉시 구현하지 않고 재현 화면, 플레이 구간과 영향을 먼저 확인한다.
3. 기존 기능을 없애거나 플레이 규칙을 바꾸는 안은 사용자 확정 전까지 구현하지 않는다.
4. 확정된 개선은 영향받는 기획 문서, 설계 모듈, 코드와 회귀 테스트를 연결한다.
5. 구현 완료는 끝이 아니다. 동일 조건에서 다시 플레이해 문제가 실제로 줄었는지 확인해야 `완료`로 처리한다.
6. 해커톤 제출 전에는 새 콘텐츠보다 첫 30초 이해도, 핵심 재미 전달, 오류 없는 실행과 3분 시연 품질을 우선 평가한다.

## 3. 우선순위 정의

- `P0`: 제출·실행·승패 진행을 막거나 심사위원이 핵심 플레이에 도달하지 못하게 하는 문제
- `P1`: 첫인상, 핵심 재미 전달, 조작 이해와 전투 가독성을 크게 떨어뜨리는 문제
- `P2`: 완성도와 일관성을 낮추지만 플레이 진행은 가능한 문제
- `P3`: 제출 후에도 다듬을 수 있는 세부 개선

## 5. 상세 항목

### IMP-001 — MOBA 문법이 굴착 정체성보다 먼저 보일 가능성

- 상태: `검증 대기`
- 문제 제기 근거:
  - 전투 화면에 영웅, 기본 공격과 4개 기술, 레벨·경험치, 자동 진군대, 미니맵, 부활, 웨이브와 양 팀 코어 체력이 함께 표시된다.
  - 위 요소는 여러 MOBA에서 널리 사용하는 익숙한 전투 문법이므로 처음 보는 플레이어가 게임을 빠르게 `MOBA`로 분류할 수 있다.
  - 이 게임의 고유 요소인 `흙을 직접 파고 막아 진군로를 바꾼다`는 인과가 더 늦게 보이면 차별점이 사라진 것이 아니라 첫인상에서 가려질 수 있다.
- 현재 판단:
  - 롤 또는 특정 MOBA의 복제라는 결론은 아니다.
  - 세계관, 미술, 가변 지형과 굴착 기반 진군 구조는 별개의 정체성을 가진다.
  - 실제 위험도는 신규 플레이어 관찰 전까지 확정하지 않는다.
- 확인 방법:
  1. 게임 설명을 듣지 않은 플레이어에게 전투 시작부터 30초간 플레이하게 한다.
  2. `무슨 게임으로 보였는지`, `가장 먼저 이해한 행동`, `승리에 중요한 행동`을 각각 한 문장으로 답하게 한다.
  3. 세 질문 중 굴착·길·경로 변경이 자발적으로 언급되는 비율을 기록한다.
  4. 실제 플레이 영상에서 첫 굴착, 첫 경로 변경, 첫 영웅 교전 시점을 비교한다.
- 개선 후보 — 미확정:
  - 첫 전투 구간에서 굴착 선택과 진군 경로 변화를 영웅 교전보다 먼저 경험하게 한다.
  - HUD에서 굴착·매립·진군 지시·건설의 시각 우선순위를 조정한다.
  - 제출 영상과 썸네일의 첫 장면을 경로 생성과 병력 방향 전환으로 구성한다.
  - A/B를 고정 라인처럼 보이게 표현하는 용어와 안내 방식을 검토한다.

### IMP-002 — HUD 정보 밀도와 조작 진입 장벽

- 상태: `검증 대기`
- 문제 제기 근거:
  - 건설, 두 분대 지시, 영웅 상태, 공용 행동, 아이템과 4개 기술을 한 화면에 동시에 표시한다.
  - 작은 글씨와 다수의 단축키 안내가 전투 화면 아래에 집중되어 있다.
- 확인 방법:
  - 1920×1080 PC, 작은 노트북, 대표 모바일 가로 화면에서 글자와 버튼 식별 여부를 캡처한다.
  - 설명 없이 이동·굴착·기술·진군 지시를 수행하기까지 걸린 시간과 오입력을 기록한다.
- 개선 후보 — 미확정:
  - 상황별로 사용하지 않는 조작군을 접거나 단계적으로 공개한다.
  - 핵심 행동과 보조 행동의 크기·색·위치를 재분류한다.
  - 항상 표시하는 긴 조작 문장을 짧은 상황 안내로 교체한다.

### IMP-003 — 전투 화면의 아트 일관성

- 상태: `검증 대기`
- 문제 제기 근거:
  - 유승천은 고정밀 4방향 동작을 사용하지만 다른 영웅 다수는 공용·보조 시트 조합을 사용한다.
  - 영웅, 진군대, 거점, 설치물과 절차적 지형은 서로 다른 제작 단계를 거쳤다.
- 확인 방법:
  - 대표 영웅 3명과 세 종족 진군대가 함께 나오는 전투 화면을 동일한 카메라 배율로 비교한다.
  - 실루엣, 픽셀 크기, 광원, 외곽선, 애니메이션 프레임과 팀 식별성을 항목별로 점검한다.
- 개선 후보 — 미확정:
  - 제출 시연 대표 영웅과 자주 노출되는 진군대의 우선 보정 범위를 정한다.
  - 전체 재제작이 아니라 색·외곽선·그림자·표시 크기의 공통 후처리부터 검토한다.

### IMP-004 — 메뉴와 실제 전투의 완성도 격차

- 상태: `검증 대기`
- 문제 제기 근거:
  - 메인 메뉴는 로고, 방송 UI와 지하 생존 분위기가 강하지만 전투는 정보 중심 HUD와 작은 월드 화면으로 전환된다.
- 확인 방법:
  - 메인 메뉴부터 영웅 선택, 로딩, 첫 전투 30초를 끊김 없이 녹화한다.
  - 분위기, 글자 크기, 색상, 화면 점유율과 소리의 일관성이 깨지는 지점을 표시한다.
- 개선 후보 — 미확정:
  - 메뉴의 경고 방송·공업 UI 언어를 전투 HUD의 핵심 요소에만 이어 붙인다.
  - 월드 화면 점유율과 주변 검은 여백의 의도성을 다시 확인한다.

### IMP-005 — 넓은 콘텐츠 범위가 만드는 마감 분산

- 상태: `검증 대기`
- 문제 제기 근거:
  - 플레이 가능한 영웅 12명, 다수 대전 맵, 5장 캠페인, 1:1·2:2와 온라인 흐름이 동시에 존재한다.
  - 기능의 양은 강점이지만 심사위원이 짧게 플레이할 때 완성도가 낮은 조합이나 구간을 먼저 만날 위험이 있다.
- 확인 방법:
  - 각 모드와 대표 영웅의 첫 3분을 녹화하고 치명적 오류, 조작 이해, 아트 완성도와 핵심 재미 전달을 등급화한다.
  - 제출판에서 첫 화면에 노출할 경로와 후순위 콘텐츠를 분리한다.
- 개선 후보 — 미확정:
  - 콘텐츠 삭제 여부보다 심사 기본 진입 경로와 대표 조합을 먼저 정한다.
  - 제출 직전에는 신규 콘텐츠를 추가하지 않고 대표 경로의 품질을 우선한다.

### IMP-006 — 첫 30초의 굴착 인과 전달

- 상태: `검증 대기`
- 문제 제기 근거:
  - 현재 대전 시작 화면은 코어 주변 열린 공간, 영웅과 진군대 출전이 먼저 보인다.
  - 플레이어가 굴착하지 않아도 초기 교전이 시작되면 `길을 만드는 게임`이라는 설명이 늦어질 수 있다.
- 확인 방법:
  - 대표 맵별 첫 30초 동안 필수 굴착 횟수, 첫 전략 지점 입력과 진군대의 실제 방향 전환 시점을 기록한다.
  - 굴착 전후의 진군 경로를 화면만 보고 이해할 수 있는지 확인한다.
- 개선 후보 — 미확정:
  - 제출 대표 맵의 시작 구간에서 서로 다른 굴착 선택을 빠르게 제시한다.
  - 첫 경로 변화에 짧은 시각·음향 피드백을 추가하는 안을 검토한다.

### IMP-007 — 공개·제출 패키지 검증

- 상태: `검증 대기`
- 문제 제기 근거:
  - `5. 오픈/`에는 준비 항목만 있고 최종 플레이 주소, 조작법, 소개, 썸네일, 3분 영상, 시연 대본과 Codex 활용 설명의 완료본이 아직 연결되지 않았다.
  - 기준 문서에 적힌 기존 공개 주소는 현재 프로젝트명 이전의 레거시 주소로 표시돼 있다.
- 확인 방법:
  - 로그아웃·새 브라우저에서 외부 주소 접속부터 대표 플레이 종료까지 수행한다.
  - 공식 제출 양식의 필수·선택 항목과 파일 형식, 영상 길이를 대조한다.
- 개선 후보 — 미확정:
  - 최종 공개 주소와 제출 자료의 단일 체크리스트를 `5. 오픈/`에 작성한다.
  - 3분 영상은 게임 소개보다 실제 굴착과 경로 변화 장면을 우선한다.

### 함께 구현할 신규 기본 대전 모드 방향

- 신규 기본 모드명: `비밀 굴착전`
- 기존 대전 모드: 별도 `개방 전선전`으로 보존
- 컴퓨터 대전과 같이하기의 모드 선택 구조를 분리하고, 검증을 통과한 `비밀 굴착전`을 기본 선택으로 전환했다.
- 준비 단계는 2분이다. 상대 코어 위치는 처음부터 표시하고 상대의 전용 터널은 숨긴다.
- 준비 단계에는 자기 팀 영웅만 표시하고 상대 영웅의 캐릭터·이름표·체력 바·미니맵 표식과 위치를 직접 노출하는 효과를 모두 숨긴다. 양 팀에서 보이는 상대 정보는 거점 위치뿐이다.
- 보이지 않는 공격을 막기 위해 준비 단계에는 적 영웅과의 공격·투사체 피해·직접 충돌을 비활성화하고 진군대 웨이브는 출전시키지 않는다.
- 준비 단계에는 공통 굴착 속도와 영웅별 4번 지형 행동의 재사용을 보정하고, 광석·골드 확보, 방어 준비와 A/B 공격로 구성을 수행한다.
- 타일은 청팀 전용, 적팀 전용, 공동 터널을 구분한다. 양 팀 굴착이 같은 타일에서 겹치면 해당 부분만 공동 터널이 된다.
- 준비 중 공동 터널은 접촉 격벽으로 막고 양 팀에 국소 진동 경고만 제공한다. 상대 터널 전체는 공개하지 않는다.
- 2분 종료 시 지반을 고정해 추가 굴착·매립과 4번 지형 행동을 비활성화한다. 현재 `개방 전선전`의 4번 기능은 변경하지 않는다.
- 개전 순간 아군 거점에 연결된 `이용 가능 터널망`을 스캔 광원과 아군색 바닥 테두리로 표시한다. 공동 터널은 황색 경고 무늬, A/B 공격로는 문자와 서로 다른 형태의 진행 화살표로 구분하며 상대 전용 터널은 공개하지 않는다.
- A/B가 아닌 이용 가능 터널과 막다른 길은 테두리만 표시해 `갈 수 있는 길`과 `현재 진군하는 길`을 구분한다. 전투 중 상대 영웅은 기존 일반 시야·안개 규칙에 따라 발견될 때만 보인다.
- 진군대는 완성된 모든 터널에 무조건 분산하지 않는다. 게임이 유효 공격로를 탐지해 A/B를 추천하고, 사용자가 두 공격로와 `균등 50:50 / A 집중 75:25 / B 집중 25:75`를 선택한다.
- 선택되지 않은 추가 터널은 영웅 이동, 광석, 후퇴, 기만과 다음 웨이브 예비 경로로 유지한다.
- 전투 단계에는 아군 진군대와 영웅이 `자기 팀 전용 + 공동` 터널만 사용할 수 있다. 상대 전용 터널은 이용할 수 없다.
- 전체 경기는 `2분 준비 + 4분 침공 = 총 6분`이며 코어 파괴를 우선하고 시간 종료 판정은 코어 체력→방어막→무승부 순서다. 전선 개척도·처치·굴착량은 판정에서 제외한다.
