# 서울 지하 999M 운영 배포 구성 v0.1

- 상태: 운영 배포 기준 확정, 경쟁 서비스 서버 권위화는 후속 필수
- 기준일: 2026-08-25
- 대상: `4. 개발/seoul-999m-below`

## 1. 현재 서버 경계

- 프런트와 서버 렌더링은 vinext 및 Cloudflare Worker 한 배포물로 구성한다.
- `worker/index.ts`가 정적 앱 요청과 `/api/rooms` 방 API를 처리한다.
- `RoomHub` Durable Object 한 개가 방 하나를 소유하고 방 코드, 참가자, 준비, 경기 시드, 명령, 방장 스냅샷, 승패와 이탈 상태를 저장한다.
- 게스트 친선전에는 별도 D1이 필요하지 않다. 계정, 영구 진행, 랭킹, 신고·제재, 결제와 운영 이력을 추가할 때 D1 또는 관리형 PostgreSQL을 별도로 붙인다.
- 현재 전투 판정은 방장 클라이언트가 권위 스냅샷을 WebSocket으로 발행하는 제출용 구조다. 공개 경쟁전과 유료 서비스 전에는 전투 판정·난수·승패를 Durable Object의 고정 tick 서버 시뮬레이션으로 옮겨야 한다.

## 2. 저장소에 준비된 운영 설정

- `wrangler.jsonc`: Worker 이름, 엔트리, 정적 에셋 `ASSETS`, `ROOMS` Durable Object, SQLite 저장소 생성 마이그레이션, 관측 기능을 선언한다.
- `vite.config.ts`: 로컬과 빌드가 같은 `wrangler.jsonc`를 읽으므로 개발과 운영의 방 바인딩 차이를 줄인다.
- `npm run deploy`: 프로덕션 빌드 성공 뒤 Wrangler 배포를 실행한다.
- 비밀키는 현재 게임에 필요하지 않다. 향후 인증·결제·외부 API 키는 저장소나 클라이언트 환경 변수에 넣지 않고 Worker Secret으로 등록한다.

## 3. 운영자가 최초 한 번 할 일

1. Cloudflare 계정을 만들고 Workers 사용이 가능한 계정을 선택한다.
2. 프로젝트 폴더에서 `npm ci`, `npx wrangler login`, `npm test`를 순서대로 실행한다.
3. `npm run deploy`를 실행한다. 최초 배포 때 `RoomHub` SQLite Durable Object 네임스페이스가 생성된다.
4. 발급된 `*.workers.dev` 주소에서 메인 화면, 방 생성, 다른 브라우저 참가, 전투 시작, 참가자 이탈 종료를 확인한다.
5. 자체 도메인이 있으면 Cloudflare DNS에 도메인을 연결한 뒤 Worker의 Domains & Routes에서 Custom Domain을 추가한다. 인증서와 라우팅은 Cloudflare가 관리한다.
6. 운영용과 스테이징용 Worker 이름·도메인·데이터를 분리한다. 운영 Durable Object를 개발 환경에서 재사용하지 않는다.

## 4. 배포마다 할 일

1. `npm test`와 실제 두 브라우저 온라인 스모크 테스트를 통과한다.
2. 변경된 Durable Object 클래스 생명주기가 있으면 마이그레이션 또는 class export 변경을 먼저 검토한다. 이미 배포된 마이그레이션 태그를 수정하거나 삭제하지 않는다.
3. `npm run deploy` 뒤 메인·캠페인·컴퓨터 대전·방 생성 API를 확인한다.
4. Worker 오류율, Durable Object 요청 지연, 방 생성 실패, 이탈 종료율을 관측한다. 장애 시 직전 검증 버전으로 되돌린다.

## 5. 공개 상용화 전 필수 보강

- 현재 WebSocket 방 전송 위의 호스트 권위 스냅샷을 서버 권위 고정 tick 및 압축 상태 delta로 교체한다.
- 명령 속도 제한, 좌표·재사용 대기시간·자원·피해 검증과 리플레이/신고 근거를 서버에 둔다.
- 계정 인증, 닉네임 정책, 개인정보 처리방침, 이용약관, 연령·지역 정책과 데이터 삭제 절차를 마련한다.
- D1/PostgreSQL 백업, Durable Object 장애 복구, 로그 보존 기간, 알림과 운영 대시보드를 정한다.
- 부하 테스트로 동시 방 수, 방당 전송량, WebSocket 재접속과 배포 중 연결 유지 여부를 검증한다.

## 6. 비밀정보 규칙

- `.env*`, 결제 키, 인증 비밀, Cloudflare API 토큰은 Git에 커밋하지 않는다.
- 로컬은 `.dev.vars` 또는 무시된 환경 파일을 사용하고 운영은 `wrangler secret put <NAME>` 또는 Cloudflare 대시보드의 Secret을 사용한다.
- 공개 클라이언트 번들에 포함되는 값은 비밀이 아니다. 권한이 필요한 판단과 키 사용은 Worker 내부에서만 수행한다.

## 7. 현재 WebSocket 운영 경계

- Worker와 Durable Object가 같은 배포물에 있으므로 별도 WebSocket 서버나 포트를 운영하지 않는다. 로컬은 Wrangler가 `ws://localhost`, 배포 환경은 같은 도메인의 `wss://` 연결을 처리한다.
- `RoomHub`는 Hibernation API로 방 연결을 수락하며 참가자 인증정보는 WebSocket attachment에 보관한다. 연결 단절 판정은 storage alarm을 사용해 인스턴스 휴면과 무관하게 실행한다.
- 배포 스모크 테스트에는 두 브라우저 로비 갱신, 전투 입력, 5초 네트워크 단절 뒤 재접속, 명시적 나가기 종료와 유예시간 초과 종료를 포함한다.
- WebSocket 전환은 별도 D1이나 비밀키를 요구하지 않는다. Cloudflare 계정에서 기존 `ROOMS` Durable Object 바인딩과 현재 SQLite 마이그레이션만 정상 생성되면 된다.
