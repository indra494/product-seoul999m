# 서울 지하 999M 콘텐츠 모듈 표준 설계

## 문서 상태

- 상태: `구조 원칙 확정 / 세부 수치와 콘텐츠 제안 검토 중`
- 작성일: 2026-08-20
- 목적: 캐릭터, 스킬, 투사체, 상태 효과와 설치물을 추가해도 핵심 전투 로직을 수정하지 않는 데이터 중심 구조를 정의한다.
- 관련 기획: `2. 기획/서울지하999M-게임-기획-초안.md`
- 기존 구현: `4. 개발/seoul-999m-below/app/Seoul999mBelow.tsx`

## 1. 확정 요구사항

- 캐릭터와 설치물은 공통 정의 형식을 사용한다.
- 공격 범위, 피격 범위, 피해, 사거리, 공격 방식, 시전 시간과 재사용 대기시간을 데이터로 관리한다.
- 근접, 원거리, 광역, 투사체, 돌진, 함정과 지형 변경을 재사용 행동 모듈로 제공한다.
- 캐릭터 추가 시 기존 전투 엔진의 조건문과 핵심 로직을 직접 수정하지 않는다.
- 스프라이트, 애니메이션, 시각 효과와 효과음도 게임 로직과 분리한 ID 참조로 연결한다.
- 포탑, 차단벽, 감지기와 함정 등 설치물도 같은 원칙으로 추가한다.

## 2. 현실적인 제약

- 이미 존재하는 행동 모듈의 조합으로 표현할 수 있는 콘텐츠는 데이터와 에셋만 추가한다.
- 순간이동, 분신, 시간 역행처럼 기존 모듈로 표현할 수 없는 규칙은 새 행동 모듈을 한 번 구현해야 한다.
- 새 모듈은 특정 캐릭터 이름을 알지 못해야 하며 이후 다른 캐릭터와 설치물에서도 재사용할 수 있어야 한다.
- 캐릭터마다 별도의 거대한 `if/else`를 추가하는 방식은 금지한다.

## 3. 전체 구조

```text
입력 또는 AI 명령
       ↓
스킬 사용 검증 ── 사거리·자원·쿨다운·상태
       ↓
행동 모듈 실행 ── 근접 / 투사체 / 돌진 / 범위 / 설치 / 지형 변경
       ↓
판정 생성 ────── 원 / 부채꼴 / 선 / 사각형 / 단일 지점
       ↓
효과 해결 ────── 피해 / 회복 / 밀치기 / 둔화 / 기절 / 굴착 / 매립
       ↓
전투 이벤트 ──── 피격·처치·타일 파괴·건설·카메라·사운드·VFX
       ↓
화면 표현
```

전투 엔진은 콘텐츠 이름이 아니라 `행동`, `판정 형태`, `대상`, `효과`만 처리한다.

## 4. 공통 단위와 판정 규격

- 거리와 크기: `타일` 단위. 소수 허용. 예: `range: 1.25`.
- 시간: 밀리초. 예: `cooldownMs: 5200`.
- 각도: 도. 예: `angleDeg: 80`.
- 피해: 정수. 유닛, 구조물, 코어 방어막과 지형 피해를 분리한다.
- 좌표와 방향: 시뮬레이션의 월드 좌표를 사용하며 렌더링 픽셀 좌표와 분리한다.
- 사거리: 공격자 충돌 중심에서 판정 형태의 가장 먼 경계까지를 타일 단위로 저장한다. 캐릭터 대표 사거리는 기본 공격 정의에서 읽고 기술마다 별도 판정 크기를 사용한다.
- 레벨 성장으로 사거리를 자동 확대하지 않는다. 사거리 변경은 특성 또는 설치물 레벨 정의의 명시적 수정값으로만 적용한다.

### 판정 형태

| 형태 | 필수 값 | 대표 용도 |
|---|---|---|
| `circle` | 반지름 | 폭발, 전기 충격, 회복 |
| `cone` | 사거리, 각도 | 드릴 휘두르기, 화염 |
| `line` | 길이, 폭 | 돌진, 관통 사격, 레이저 |
| `rectangle` | 길이, 폭 | 벽, 지속 장판 |
| `point` | 좌표 | 함정, 소환, 단일 설치 |

### 공격 전달 방식

- `melee`: 시전자의 현재 위치에서 즉시 판정
- `projectile`: 속도와 수명을 가진 투사체 생성
- `dash`: 시전자 이동과 경로 판정을 함께 수행
- `area`: 지정 위치에 즉시 또는 지연 판정
- `zone`: 일정 시간 남는 범위 생성
- `trap`: 숨겨진 작동 조건을 가진 범위 생성
- `deploy`: 설치물 생성

### 대상 필터

- 진영: `enemy`, `ally`, `self`, `neutral`
- 분류: `hero`, `minion`, `turret`, `buildable`, `coreShield`, `core`, `terrain`
- 상태: 생존, 전투불능, 은신, 현재 시야 안 등

### 종족별 설치물 등록 정책

- 목표 로스터는 휴먼, 버그본, AI 로봇의 종족별 3종, 총 9종이다.
- 공통 엔진은 부채꼴 다중 투사체, 다중 대상 근접 타격, 지속 피해 투사체, 직선 관통, 지연 광역 투사체와 이동 차단을 재사용 행동 모듈로 제공한다.
- 배치기는 코어 중심의 최소·최대 반경, 시야, 겹침과 출전 경로 보존을 공통 검증한다.
- 철거 환급은 `floor(cost * maxRefundRatio * hp / maxHp)`로 계산한다.
- 제출판은 레벨 1로 고정하지만 정의 파일은 `maxLevel`과 레벨별 프레젠테이션 참조를 허용한다.
- 종족별 명칭, 수치와 제출 우선순위는 `2. 기획/종족별-설치물-기획-v0.1.md`를 기준으로 한다.

## 7. 캐릭터 시각 표준

- 제출판 기준 프레임 크기: `48×48px`를 우선 검토한다.
- 방향: 상·하·좌·우 4방향. 일정상 8방향은 제외한다.
- 필수 애니메이션: 대기, 이동, 기본 공격, 각 스킬 시전, 피격, 전투불능, 부활.
- 모든 캐릭터는 색상만 바꾸지 않고 머리, 몸통, 무기와 이동 자세의 실루엣이 달라야 한다.
- 캐릭터 ID와 스프라이트시트 ID는 분리해 동일 로직에 다른 외형을 연결할 수 있어야 한다.

```ts
type PresentationDefinition = {
  spriteSheetId: string;
  animations: Record<string, string>;
  portraitId: string;
  selectionIconId: string;
  shadowId: string;
};

type CueDefinition = {
  castAnimation?: string;
  vfxId?: string;
  impactVfxId?: string;
  sfxId?: string;
  hitStopMs?: number;
  cameraShake?: number;
};
```

타격감은 피해 수치가 아니라 `예비 동작 → 판정 → 40~70ms 히트스톱 → 피격 자세 → 방향성 파편 → 효과음`을 한 묶음으로 표준화한다.

## 8. 첫 적용 캐릭터 — 유승천

도윤은 플레이어 캐릭터 자리에서 제거하고, 첫 플레이 가능 휴먼은 유승천으로 교체한다. 최종 캐릭터 기준은 `2. 기획/휴먼-캐릭터-디자인-v0.1.md`를 우선한다. 현재 `Seoul999mBelow.tsx` 적용본은 디자인과 핵심 기술의 체감 확인을 위한 임시 구현이며, 아래 데이터 구조로 분리하는 작업은 아직 남아 있다.

### 시각 콘셉트

- 키가 작고 날렵한 40대 한국 남성이며 짙은 피부톤, 짧은 검은 머리와 뚜렷한 이목구비를 가진다.
- 남색·회백색 짝퉁 축구 트레이닝복, 정강이 보호대와 낡은 풋살화를 착용한다.
- 한 손에는 깨진 플라스틱 장난감검, 다른 쪽에는 테이프·노출 전선·찌그러진 외장의 파란 고철 드릴을 장착한다.
- 상하좌우 방향에서 머리, 흰 가슴 띠, 장난감검과 드릴의 위치가 구분되어야 한다.
- 장비는 우스꽝스럽지만 달리기와 공격 궤적은 빠르고 능숙하게 표현한다.

### 전투 구성 제안

| 입력 | 이름 | 판정 | 제안 효과 |
|---|---|---|---|
| 클릭 | 장난감검 베기 | 짧은 부채꼴 | 근접 단일 피해, 황색·분홍 플라스틱 참격 궤적 |
| 1+클릭 | 회오리베기 | 자신 중심 반경 1.7 | 주변 적 광역 피해, 청색·황색 이중 회전 궤적 |
| 2+클릭 | 돌격 찌르기 | 길이 4 직선 돌진 | 경로의 적 피해, 벽과 구조물 앞에서 정지 |
| 3 | 파란 드릴 전개 | 주변 8타일 | 파괴 가능한 벽 즉시 철거, 기반암 제외 |
| 4 | 포탑 건설 | 거점 주변 지정 슬롯 | 현재 프로토타입의 임시 입력. 필살기 슬롯과 건설 UI 분리는 후속 작업 |
| E | 원상복구 | 전방 한 칸 | 빈 땅굴 매립 |

유승천은 빠른 이동과 근접 광역 공격으로 열린 통로를 선점하고, 파란 드릴로 포위 공간을 즉시 전투장으로 바꾸는 스피드형 딜러로 정의한다.

## 9. 코드 디렉터리 목표

```text
game/
  engine/          고정 틱, 충돌, 피해, 상태, 이벤트
  actions/         melee, projectile, dash, area, deploy, terrain
  systems/         movement, combat, vision, AI, build, objective
  content/
    characters/    캐릭터 정의
    skills/        스킬 정의
    buildables/    설치물 정의
    projectiles/   투사체 정의
    statuses/      상태 효과 정의
    registry.ts    ID 등록과 참조 검증
  presentation/    스프라이트, 애니메이션, VFX, SFX, 카메라
  campaign/        스테이지, 목표, 웨이브, 보상 데이터
```

React는 메뉴와 HUD를 관리하고 Canvas는 `engine`이 만든 읽기 전용 스냅샷을 그린다. 게임 규칙은 React 컴포넌트 내부에 두지 않는다.

## 10. 검증과 디버그 도구

- 시작 시 모든 콘텐츠 ID 중복, 누락 참조와 잘못된 수치를 검사한다.
- 공격 범위, 피격 범위, 시야, 이동 충돌과 설치 가능 칸을 켜고 끌 수 있는 디버그 오버레이를 만든다.
- 같은 입력과 시드가 같은 결과를 내는 시뮬레이션 테스트를 작성한다.
- 캐릭터마다 기본 공격, 모든 스킬, 전투불능과 부활을 자동 테스트한다.
- 설치물마다 배치 불가, 배치 성공, 표적 선택, 공격, 파괴를 자동 테스트한다.

## 11. 전환 순서

1. 현재 `Seoul999mBelow.tsx`에 섞인 게임 계산을 독립 엔진으로 옮긴다.
2. 공통 판정 형태, 효과, 행동과 이벤트 타입을 만든다.
3. 현재 유승천의 행동을 새 데이터 규격으로 재현해 회귀 테스트한다.
4. 유승천 스프라이트와 기본 공격·회오리베기·돌격 찌르기·파란 드릴 전개를 완성한다.
5. 볼트 포탑, 전기코일과 차단벽을 공통 설치물 규격으로 구현한다.
6. 캠페인 첫 임무는 이 엔진과 콘텐츠 데이터만 사용해 구성한다.
7. 첫 임무가 완성된 뒤 두 번째 캐릭터 추가 비용을 검증한다.

## 12. 완료 기준

- 유승천의 수치를 바꿀 때 엔진 파일을 수정하지 않는다.
- 동일한 공격 정의를 영웅, 자동 유닛과 포탑이 함께 사용할 수 있다.
- 새 투사체 캐릭터를 데이터와 에셋만 등록해 실행할 수 있다.
- 설치물 세 종류가 서로 다른 판정, 표적 선택과 연출을 가진다.
- 공격 범위와 실제 피격 결과가 디버그 오버레이와 일치한다.
- 캠페인과 추후 네트워크 서버가 동일한 시뮬레이션 모듈을 사용한다.

## 13. 성장·치명타·AI 동료 확장

- 레벨, 경험치, 진군 웨이브 단계와 선택 특성은 콘텐츠 정의에 저장하고 전투 엔진은 캐릭터 이름을 알지 않는다.
- 설치물 인스턴스는 `definitionId`, `level`, 현재 HP와 강화 상태만 가지며 레벨별 수치는 정의에서 계산한다.
- 치명타 판정은 공격 이벤트 해결 시 한 번만 수행하고, 코어·방어막·지형·지속 피해처럼 제외된 대상과 효과를 공통 필터에서 차단한다.
- 누적 보정형 치명타 상태와 난수 시드는 서버 권한 시뮬레이션에 포함해 재현 가능하게 만든다.
- 두 번째 영웅은 플레이어 영웅과 동일한 엔티티를 사용하고 `humanInput` 또는 `aiController`만 교체한다. 네트워크 협동에서도 엔티티를 다시 만들지 않고 조작 권한만 이전한다.
- 팀 경험치는 하나의 공유 상태로 관리해 플레이어와 AI 사이의 막타 경쟁을 제거한다.
- 관련 기획과 1차 수치는 `2. 기획/자동-진군대-성장-기획-v0.1.md`를 기준으로 한다.
- 종족 밸런스 프로필은 새 콘텐츠의 수치 검토와 자동 검증에 사용하는 목표값이다. 영웅·진군대·설치물 정의에 이미 확정 수치가 들어간 뒤 런타임에서 배율을 다시 곱하지 않는다.
- 콘텐츠 검증기는 휴먼 대비 버그본의 이동속도와 직접 DPS, AI의 1회 피해와 공격 예고시간이 `2. 기획/종족별-전투-밸런스-v0.1.md`의 허용 범위를 벗어나면 경고한다.
