# 대전·네트워크·AI·맵·오디오 설계 v0.1

## 1. 목적과 제약

- 기준 기획: `2. 기획/대전-모드-핵심-기획-v0.1.md`
- 컴퓨터와 온라인 1:1·2:2가 같은 규칙, 맵, 캐릭터 행동과 AI를 사용한다.
- 현재 React Canvas 화면에 결합된 전투 상태를 순수 TypeScript 시뮬레이션으로 단계적으로 분리한다.
- 배포 기반은 기존 Vinext와 Cloudflare Worker를 유지한다.
- 첫 완성 순서는 로컬 컴퓨터 대전 수직 슬라이스, 동일 엔진 테스트, 방 코드 온라인 순이다.

## 2. 고수준 구조

```text
메뉴·로비 UI
    │ MatchConfig / PlayerCommand
    ▼
MatchSession ───── BattleMapDefinition
    │
    ├─ BattleSimulation ── 캐릭터·진군대·설치물·투사체 시스템
    ├─ HeroBrain / MinionBrain ── 사람 입력과 같은 Command 생성
    └─ BattleEvents ── 렌더링·HUD·BGM·효과음 소비

로컬 컴퓨터 대전: 브라우저 안 MatchSession
온라인 대전: Cloudflare Durable Object 안 MatchSession
클라이언트: 입력 전송 + 로컬 예측 + 서버 스냅샷 보정
```

AI가 유닛 위치를 직접 바꾸거나 별도 피해 함수를 호출하지 않는다. 사람과 동일한 이동·공격·기술·건설 명령을 만들어 시뮬레이션에 전달해야 판정 차이가 생기지 않는다.

## 3. 기준 데이터

### MatchConfig

```ts
type MatchConfig = {
  kind: "computer" | "online";
  teamSize: 1 | 2;
  mapId: BattleMapId;
  seed: number;
  teams: [TeamConfig, TeamConfig];
};
```

- 한 팀의 모든 영웅은 같은 종족이다.
- 팀 안의 영웅 ID는 중복할 수 없다.
- 컴퓨터 상대는 플레이어와 다른 종족에서 시드 기반으로 선택한다.
- 무작위 결과는 `Math.random()`이 아니라 MatchConfig의 시드로 재현한다.

### PlayerCommand

- 이동/굴착 목적지
- 기본 공격과 기술 슬롯/조준 방향
- A/B 전략 지점과 태세
- 건설/강화/철거
- 아이템, 메우기와 생존기

각 명령은 `matchId, slotId, sequence, clientTick`을 가진다. 서버와 로컬 AI가 같은 형식을 사용한다.

## 4. 전투 시뮬레이션 분리 순서

1. `matchConfig.ts`: 편성 검증, 시드 무작위, 1:1·2:2 슬롯
2. `battleMaps.ts`: 맵 지형·거점·자원·건설 구역·위험 요소
3. `heroBrain.ts`: 영웅 판단과 Command 생성
4. `combatAudio.ts`: BattleEvent를 BGM/SFX로 변환
5. `battleSimulation.ts`: 현재 Canvas 내부의 상태 갱신을 순수 모듈로 이동
6. `matchRoom.ts`: 방 코드·준비·재접속·AI 인계

Canvas는 최종 상태를 그리기만 하며 맵 규칙이나 AI 판단을 포함하지 않는다.

## 5. 영웅 AI

### 5.1 계층

- 전략 계층(0.8~1.5초): 공격, 방어, 합류, 우회, 회복, 거점 보강 중 목표 선택
- 전술 계층(0.15~0.35초): 표적, 거리, 기술, 회피 방향 결정
- 반응 계층(매 틱): 위험 투사체 회피, 막힘 복구, 즉시 공격 가능 여부

### 5.2 효용 점수

각 후보 행동은 다음을 합산해 가장 높은 행동을 선택한다.

- 적 처치 가능성
- 내 생존 위험
- 아군 구조 가치
- 코어 공격/방어 긴급도
- 사거리와 시야
- 기술 재사용 및 자원
- 다수 적중 가능성
- 역할 적합도(탱커·지원·포병·기동·공성)
- 맵 위험과 통로 폭
- 최근 반복 행동 감점

점수에 작은 시드 기반 변동만 넣어 완전히 같은 행동의 반복을 막는다. 난이도는 피해량을 조작하기보다 판단 주기, 예측 시간, 위험 허용치와 협동 정확도로 조절한다.

### 5.3 협동 규칙

- 2:2 AI는 동료가 이미 노리는 빈사 적에 무조건 겹치지 않고, 처치 가능할 때만 집중한다.
- 지원가는 부상 아군 2명, 코어 위험, 공격 기회 순으로 치료 가치를 비교한다.
- 탱커는 원거리 동료와 적 사이를 점유하고 밀치기를 절벽·증기·포탑 사선과 결합한다.
- 굴착 AI는 최단거리뿐 아니라 통로 폭, 매복 위험과 진군대 합류 시간을 평가한다.
- 1.5초 이상 막히면 다른 경로를 탐색하고 5초 이상 실패하면 상위 목표를 다시 고른다.

## 6. 맵 모듈

`BattleMapDefinition`은 ID, 이름, 설명, 56×36 지형 생성기, 거점 위치, 초기 방, 자원 분포, 건설 제한 구역, 전략 앵커, 위험 시스템과 BGM ID를 가진다.

다섯 맵은 동일한 렌더러와 길찾기를 사용하고 데이터와 위험 시스템만 다르게 한다.

| ID | 맵 | 고유 시스템 |
|---|---|---|
| central-exchange | 서울 중앙 환승로 | 중앙 단거리와 상·하 우회로 |
| flooded-pump | 침수 펌프장 | 얕은 물 감속, 마른 측면 정비로 |
| root-lab | 뿌리 잠식 연구구 | 파괴 가능한 잔뿌리 관문과 우회 굴착 |
| freight-fork | 붕괴 화물 분기점 | 중앙 잔해와 완전 분리된 A/B 목 |
| thermal-shaft | 지열 환기 수직갱 | 순환 예고 뒤 증기 분출 |

모든 맵은 180도 회전 대칭을 기본으로 하며 코어 간 최단 굴착 비용, 광석 총량, 건설 가능 면적을 자동 테스트한다.

### 6.1 1차 구현 상태

- `battleMaps.ts`의 `applyBattleMapLayout`이 56×36 공용 그리드에 맵별 실제 지형을 생성한다.
- 스커미시 코어는 `(6, 18)`과 `(49, 18)`에 고정해 시작 거리의 무작위 편차를 제거했다.
- 얕은 물은 플레이어·영웅 AI·진군대 이동 속도를 58%로 낮춘다.
- 증기 환기구는 5.2초 주기로 경고(1.7~2.4초), 분출(2.4~3.9초), 휴지 상태를 반복하며 노출 유닛에 0.7초마다 피해를 준다.
- 영구 절벽·깊은 물·굵은 뿌리를 제외하면 모든 맵에서 두 코어 사이에 굴착 가능한 연결 경로가 존재한다.
- 캠페인 지형 생성은 기존 장별 레이아웃을 유지하고 대전 맵 생성기와 분기한다.

## 7. 오디오

### 7.1 BGM 5종

- 중앙 환승로: 92 BPM, 철도 금속 펄스와 낮은 드론
- 침수 펌프장: 78 BPM, 저역 펌프 박동과 물방울 고음
- 뿌리 잠식 연구구: 86 BPM, 불규칙 생체 리듬과 마찰음
- 붕괴 화물 분기점: 104 BPM, 컨테이너 타격과 긴장 베이스
- 지열 환기 수직갱: 112 BPM, 압력 경고 리듬과 상승 노이즈

브라우저 Web Audio로 루프를 합성해 저작권과 대용량 파일 문제를 피한다. 멜로디보다 지하 분위기와 전투 리듬을 강조하고, 같은 음형을 20초 안에 그대로 반복하지 않는다.

### 7.2 효과음 이벤트

- 이동/굴착: 흙, 암반, 뿌리, 금속을 구분
- 전투: 근접, 탄환, 산성, 레이저, 폭발, 방패, 회복
- 전장: 건설, 강화, 코어 방어막 파괴, 경고, 부활
- UI: 선택, 취소, 준비, 방 참가
- 결과: 승리와 패배

동시 진군대 교전은 같은 효과음을 50~90ms 안에 합쳐 소음과 성능 저하를 막는다. BGM, 전투, UI 버스를 분리해 개별 음량을 조절한다.

## 8. 온라인 권위 모델

- Cloudflare Durable Object 하나가 방 하나를 소유한다.
- 서버가 편성, 시드, 맵, 피해, 자원, 승패의 최종 권위를 가진다.
- 클라이언트는 20Hz 명령을 보내고 서버는 10~15Hz 상태 델타와 중요 이벤트를 보낸다.
- 로컬 영웅 이동은 예측하고 서버 상태와 오차가 작으면 부드럽게 보정한다.
- 방장은 맵과 인원만 정한다. 전투 상태에 대한 특별 권한은 없다.
- 연결 종료 후 10초 동안 슬롯을 보존하고 이후 공용 HeroBrain이 인계한다. 같은 토큰으로 재접속하면 슬롯을 돌려준다.

### 선택 이유와 대안

- 호스트 권위 방식은 빠르지만 방장 종료, 치팅과 상태 불일치 위험이 크므로 주력 모드에는 사용하지 않는다.
- 완전 락스텝은 현재 부동소수점·비결정적 랜덤·브라우저 차이 때문에 대규모 수정이 필요하다.
- 서버 권위는 초기 분리 비용이 크지만 컴퓨터 AI와 온라인이 동일해지고 판정 불일치를 가장 확실히 줄인다.

## 9. 테스트 경계

- MatchConfig: 종족 제한, 중복 금지, 시드 재현
- 맵: 대칭, 코어 연결 가능성, 자원/건설 면적 허용 오차
- AI: 12명 기술 사용, 회복/도주/코어 방어/막힘 복구 시나리오
- 오디오: 사용자 입력 전 자동 재생 금지, 이벤트 스로틀, 종료 시 모든 노드 정리
- 네트워크: 두 브라우저의 승패·체력·지형 해시 일치, 재접속, AI 인계
- 회귀: 캠페인은 같은 캐릭터 표현과 전투 행동 모듈을 계속 사용

## 10. 구현 단계

1. 로컬 MatchConfig, 5개 맵 데이터, 공용 HeroBrain, 오디오 엔진
2. 컴퓨터와 대전 1:1 완전 교체
3. 컴퓨터와 대전 2:2와 같은 종족 편성 UI
4. 전투 시뮬레이션 추출과 결정론 테스트
5. 방 코드 로비와 Durable Object
6. 온라인 1:1, 재접속, 온라인 2:2
7. 5개 맵 밸런스·AI·오디오 플레이 테스트
