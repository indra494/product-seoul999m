# 대전·네트워크·AI·맵·오디오 설계 v0.1

## 1. 목적과 제약

- 기준 기획: `2. 기획/대전-모드-핵심-기획-v0.1.md`
- 컴퓨터와 온라인 1:1·2:2가 같은 규칙, 맵, 캐릭터 행동과 AI를 사용한다.
- 현재 React Canvas 화면에 결합된 전투 상태를 순수 TypeScript 시뮬레이션으로 단계적으로 분리한다.
- 배포 기반은 기존 Vinext와 Cloudflare Worker를 유지한다.
- 첫 완성 순서는 로컬 컴퓨터 대전 수직 슬라이스, 동일 엔진 테스트, 방 코드 온라인 순이다.

## 2. 고수준 구조

```text
메뉴·로비 UI
    │ MatchConfig / PlayerCommand
    ▼
MatchSession ───── BattleMapDefinition
    │
    ├─ BattleSimulation ── 캐릭터·진군대·설치물·투사체 시스템
    ├─ HeroBrain / MinionBrain ── 사람 입력과 같은 Command 생성
    └─ BattleEvents ── 렌더링·HUD·BGM·효과음 소비

로컬 컴퓨터 대전: 브라우저 안 MatchSession
온라인 대전: Cloudflare Durable Object 안 MatchSession
클라이언트: 입력 전송 + 로컬 예측 + 서버 스냅샷 보정
```

AI가 유닛 위치를 직접 바꾸거나 별도 피해 함수를 호출하지 않는다. 사람과 동일한 이동·공격·기술·건설 명령을 만들어 시뮬레이션에 전달해야 판정 차이가 생기지 않는다.

## 3. 기준 데이터

### MatchConfig

```ts
type MatchConfig = {
  kind: "computer" | "online";
  teamSize: 1 | 2;
  mapId: BattleMapId;
  seed: number;
  teams: [TeamConfig, TeamConfig];
};
```

- 한 팀의 모든 영웅은 같은 종족이다.
- 팀 안의 영웅 ID는 중복할 수 없다.
- 컴퓨터 상대는 플레이어와 다른 종족에서 시드 기반으로 선택한다.
- 무작위 결과는 `Math.random()`이 아니라 MatchConfig의 시드로 재현한다.

### PlayerCommand

- 이동/굴착 목적지
- 기본 공격과 기술 슬롯/조준 방향
- A/B 전략 지점과 태세
- 건설/강화/철거
- 아이템, 메우기와 생존기

각 명령은 `matchId, slotId, sequence, clientTick`을 가진다. 서버와 로컬 AI가 같은 형식을 사용한다.

## 4. 전투 시뮬레이션 분리 순서

1. `matchConfig.ts`: 편성 검증, 시드 무작위, 1:1·2:2 슬롯
2. `battleMaps.ts`: 맵 지형·거점·자원·건설 구역·위험 요소
3. `heroBrain.ts`: 영웅 판단과 Command 생성
4. `combatAudio.ts`: BattleEvent를 BGM/SFX로 변환
5. `battleSimulation.ts`: 현재 Canvas 내부의 상태 갱신을 순수 모듈로 이동
6. `matchRoom.ts`: 방 코드·준비·재접속·AI 인계

Canvas는 최종 상태를 그리기만 하며 맵 규칙이나 AI 판단을 포함하지 않는다.

## 5. 영웅 AI

### 5.1 계층

- 전략 계층(0.8~1.5초): 공격, 방어, 합류, 우회, 회복, 거점 보강 중 목표 선택
- 전술 계층(0.15~0.35초): 표적, 거리, 기술, 회피 방향 결정
- 반응 계층(매 틱): 위험 투사체 회피, 막힘 복구, 즉시 공격 가능 여부

### 5.2 효용 점수

각 후보 행동은 다음을 합산해 가장 높은 행동을 선택한다.

- 적 처치 가능성
- 내 생존 위험
- 아군 구조 가치
- 코어 공격/방어 긴급도
- 사거리와 시야
- 기술 재사용 및 자원
- 다수 적중 가능성
- 역할 적합도(탱커·지원·포병·기동·공성)
- 맵 위험과 통로 폭
- 최근 반복 행동 감점

점수에 작은 시드 기반 변동만 넣어 완전히 같은 행동의 반복을 막는다. 난이도는 피해량을 조작하기보다 판단 주기, 예측 시간, 위험 허용치와 협동 정확도로 조절한다.

### 5.3 협동 규칙

- 2:2 AI는 동료가 이미 노리는 빈사 적에 무조건 겹치지 않고, 처치 가능할 때만 집중한다.
- 지원가는 부상 아군 2명, 코어 위험, 공격 기회 순으로 치료 가치를 비교한다.
- 탱커는 원거리 동료와 적 사이를 점유하고 밀치기를 절벽·증기·포탑 사선과 결합한다.
- 굴착 AI는 최단거리뿐 아니라 통로 폭, 매복 위험과 진군대 합류 시간을 평가한다.
- 1.5초 이상 막히면 다른 경로를 탐색하고 5초 이상 실패하면 상위 목표를 다시 고른다.

## 6. 맵 모듈

`BattleMapDefinition`은 ID, 이름, 설명, 56×36 지형 생성기, 거점 위치, 초기 방, 자원 분포, 건설 제한 구역, 전략 앵커, 위험 시스템과 BGM ID를 가진다.

다섯 맵은 동일한 렌더러와 길찾기를 사용하고 데이터와 위험 시스템만 다르게 한다.

| ID | 맵 | 고유 시스템 |
|---|---|---|
| central-exchange | 서울 중앙 환승로 | 중앙 단거리와 상·하 우회로 |
| flooded-pump | 침수 펌프장 | 얕은 물 감속, 마른 측면 정비로 |
| root-lab | 뿌리 잠식 연구구 | 파괴 가능한 잔뿌리 관문과 우회 굴착 |
| freight-fork | 붕괴 화물 분기점 | 중앙 잔해와 완전 분리된 A/B 목 |
| thermal-shaft | 지열 환기 수직갱 | 순환 예고 뒤 증기 분출 |

모든 맵은 180도 회전 대칭을 기본으로 하며 코어 간 최단 굴착 비용, 광석 총량, 건설 가능 면적을 자동 테스트한다.

### 6.1 1차 구현 상태

- `battleMaps.ts`의 `applyBattleMapLayout`이 56×36 공용 그리드에 맵별 실제 지형을 생성한다.
- 스커미시 코어는 `(6, 18)`과 `(49, 18)`에 고정해 시작 거리의 무작위 편차를 제거했다.
- 얕은 물은 플레이어·영웅 AI·진군대 이동 속도를 58%로 낮춘다.
- 증기 환기구는 5.2초 주기로 경고(1.7~2.4초), 분출(2.4~3.9초), 휴지 상태를 반복하며 노출 유닛에 0.7초마다 피해를 준다.
- 영구 절벽·깊은 물·굵은 뿌리를 제외하면 모든 맵에서 두 코어 사이에 굴착 가능한 연결 경로가 존재한다.
- 캠페인 지형 생성은 기존 장별 레이아웃을 유지하고 대전 맵 생성기와 분기한다.

## 7. 오디오

### 7.1 BGM 5종

- 생존본부 주파수: 76 BPM, 메뉴·작전지도용 저역 드론과 무전 펄스
- 녹슨 환승 전투: 96 BPM, 철도 금속 펄스와 컨테이너 타격
- 침수 압력 경보: 82 BPM, 저역 펌프 박동과 물방울 고음
- 군체 신호: 88 BPM, 불규칙 생체 리듬과 마찰음
- 적색선 공성: 112 BPM, 압력 경고 리듬과 상승 노이즈

`public/assets/audio/bgm`의 34~51초 스테레오 PCM WAV 5곡을 실제 루프 에셋으로 사용한다. 각 곡은 16마디 안에서 인트로→A→B→브레이크→클라이맥스로 진행하고, 코드 진행·주제 멜로디·베이스·패드·드럼·아르페지오를 분리한다. `audioCatalog.ts`가 메뉴·맵·캠페인별 곡을 선택하고 전역 `gameAudio` 싱글턴이 화면 전환에도 재생 상태를 유지하며 0.7초 교차 전환한다. 브라우저 자동 재생 정책에 따라 최초 포인터·키 입력에서 한 번만 잠금을 해제한다.

### 7.2 효과음 이벤트

- 이동/굴착: 흙, 암반, 뿌리, 금속을 구분
- 전투: 근접, 탄환, 산성, 레이저, 폭발, 방패, 회복
- 전장: 건설, 강화, 코어 방어막 파괴, 경고, 부활
- UI: 선택, 취소, 준비, 방 참가
- 결과: 승리와 패배

동시 진군대 교전은 같은 효과음을 50~90ms 안에 합쳐 소음과 성능 저하를 막는다. BGM, 전투, UI 버스를 분리해 개별 음량을 조절한다.

### 7.2.1 타격감용 샘플 계층 (2026-08-23)

- `public/assets/audio/sfx/impact/`에는 휴먼·버그본·AI·구조물 재질별 3개 타격 변형과 치명타 3개를 둔다.
- `public/assets/audio/sfx/down/`에는 휴먼·버그본·AI 전투불능 변형을 각 2개씩 두며 영웅은 진군대보다 크게 재생한다.
- `public/assets/audio/sfx/result/`의 승리·패배 스팅어는 결과 UI가 확정되는 시점에 한 번만 재생한다.
- `CombatAudio.impact/down/result`가 실제 WAV 샘플을 관리한다. 같은 종류는 55ms 안에 합치고 변형을 순환해 기관총처럼 반복되는 단일 음색을 피한다.
- 카메라 중심인 조작 영웅과 대상 사이 타일 거리를 이용해 전투음 크기를 감쇠한다. 플레이어 영웅 전투불능은 0.55초 동안 BGM을 낮춘다.
- 기존 WebAudio 단음은 UI 오류, 건설과 임시 폴백에만 유지하고 캐릭터 타격·전투불능의 주 효과음으로 사용하지 않는다.

### 7.3 스킬 보이스

- `audioCatalog.ts`에서 12명 영웅의 1·2·굴착·필살 4개 대사를 데이터로 관리한다.
- 실행 환경의 브라우저 TTS는 사용하지 않는다. 휴먼·기계지성은 캐릭터별 한국어 남녀 신경망 음성을 미리 생성한 32개 MP3로, 버그본은 별도 합성한 16개 WAV 군체음으로 재생해 PC마다 성별과 음색이 달라지는 문제를 막는다.
- 유승천은 젊은 남성 열혈 톤, 김씨는 낮고 느린 중년 남성 톤, 강력한은 굵은 남성 톤, 안서나는 빠르고 높은 여성 톤으로 분리한다. 기계지성은 낮은 음역·속도 변조와 전자 시그니처 효과를 겹친다.
- 기술마다 영웅 ID와 슬롯을 해시한 고유 2단 효과음을 대사 앞에 겹친다. 필살기는 우선순위 5로 낮은 우선순위 대사를 취소하고 일반 AI 대사가 플레이어 필살기를 덮지 못하게 하며, 발성 동안 BGM을 0.38에서 0.15로 낮춘다.
- 모든 캐릭터 보이스는 제작 원본 대비 2배 속도로 재생한다. 휴먼은 음정을 보존하고 기계지성·버그본은 속도와 음정을 함께 변조해 종족 질감을 유지한다.

## 8. 온라인 권위 모델

- Cloudflare Durable Object 하나가 방 하나를 소유한다.
- 서버가 편성, 시드, 맵, 피해, 자원, 승패의 최종 권위를 가진다.
- 클라이언트는 20Hz 명령을 보내고 서버는 10~15Hz 상태 델타와 중요 이벤트를 보낸다.
- 로컬 영웅 이동은 예측하고 서버 상태와 오차가 작으면 부드럽게 보정한다.
- 방장은 맵과 인원만 정한다. 전투 상태에 대한 특별 권한은 없다.
- 연결 종료 후 10초 동안 슬롯을 보존하고 이후 공용 HeroBrain이 인계한다. 같은 토큰으로 재접속하면 슬롯을 돌려준다.

### 선택 이유와 대안

- 호스트 권위 방식은 빠르지만 방장 종료, 치팅과 상태 불일치 위험이 크므로 주력 모드에는 사용하지 않는다.
- 완전 락스텝은 현재 부동소수점·비결정적 랜덤·브라우저 차이 때문에 대규모 수정이 필요하다.
- 서버 권위는 초기 분리 비용이 크지만 컴퓨터 AI와 온라인이 동일해지고 판정 불일치를 가장 확실히 줄인다.

## 9. 테스트 경계

- MatchConfig: 종족 제한, 중복 금지, 시드 재현
- 맵: 대칭, 코어 연결 가능성, 자원/건설 면적 허용 오차
- AI: 12명 기술 사용, 회복/도주/코어 방어/막힘 복구 시나리오
- 오디오: 사용자 입력 전 자동 재생 금지, 이벤트 스로틀, 종료 시 모든 노드 정리
- 네트워크: 두 브라우저의 승패·체력·지형 해시 일치, 재접속, AI 인계
- 회귀: 캠페인은 같은 캐릭터 표현과 전투 행동 모듈을 계속 사용

## 10. 구현 단계

1. 로컬 MatchConfig, 5개 맵 데이터, 공용 HeroBrain, 오디오 엔진
2. 컴퓨터와 대전 1:1 완전 교체

## 11. 2026-08-22 구현 결과와 검증

- `RoomHub` Durable Object가 6자리 방, 슬롯, 편성 검증, 준비/시작, 명령 로그, 연결 상태, 승패와 재대전을 영속 관리한다.
- 인증 토큰은 생성·재접속한 본인에게만 반환한다. 다른 참가자에게 제공하는 방 상태에서는 모든 플레이어 토큰을 제거한다.
- 클라이언트 명령은 이동·기본 공격·기술·굴착·A/B 노선을 공용 형식으로 전달한다. 방장은 500ms 주기로 코어와 영웅 상태 스냅샷을 올리고 상대 클라이언트는 180도 좌표 변환 후 보정한다.
- 10초 동안 heartbeat가 없는 슬롯은 AI가 인계하고 같은 토큰으로 돌아오면 사람 제어를 복구한다.
- `heroBrain.ts`는 후퇴, 코어 방어, 합류, 지원, 기본 공격, 1·2번 기술, 굴착과 필살기를 역할·체력·거리·재사용 대기시간으로 선택한다. 실행은 12명 공용 `heroActions`/`heroKits`를 사용한다.
- 자동 검증은 5개 맵의 대칭·굴착 연결성·지형 차이, AI 긴급 판단, 12명 전체 행동 키트, 캠페인 5장·대전 UI·에셋·온라인 기능을 검사한다.

현재 배포 구현은 완전한 서버 시뮬레이션이 아니라 `명령 중계 + 방장 권위 스냅샷`이다. 제출용 방 코드 대전에는 작동하지만 공개 랭크 서비스에서 요구하는 부정행위 방지 수준은 아니다. `battleSimulation.ts`로 전체 판정을 이전하는 단계는 공개 서비스화 범위로 남긴다.

### 상용 서비스 전환 구성

- `Cloudflare Worker`는 인증 토큰 검증, 방 생성·참가, 매치메이킹, 속도 제한을 담당하는 API 관문으로 유지한다.
- 방마다 하나의 `Durable Object MatchSession`을 두고 클라이언트는 이동·공격·기술 같은 입력만 전송한다. 공개 경쟁전에서는 방장 스냅샷을 폐기하고 MatchSession이 고정 tick으로 판정·승패·난수 시드를 계산하는 서버 권위형으로 전환한다.
- 전투 전송은 500ms HTTP 폴링 대신 WebSocket을 사용한다. 서버는 입력 승인 번호와 압축된 상태 delta를 방송하고, 클라이언트는 자기 영웅을 예측한 뒤 서버 값으로 완만하게 보정한다.
- `D1` 또는 별도 관리형 PostgreSQL에는 계정, 영구 진행, 시즌·랭킹, 매치 결과와 제재 기록만 저장한다. 초당 전투 좌표는 관계형 DB에 쓰지 않고 MatchSession 메모리와 선택적 리플레이 로그로 분리한다.
- 정적 에셋과 선택적 리플레이는 `R2`, 비밀키는 배포 환경 변수, 운영 지표와 오류·지연 추적은 별도 관측 계층으로 분리한다. 개발·스테이징·운영 환경과 데이터베이스를 서로 격리한다.
- 첫 상용 단계는 게스트 친선전 + WebSocket + 이탈/재접속을 완성하고, 랭크·결제·보상이 들어가기 전에 서버 권위 시뮬레이션, 인증, 악성 입력 검증과 운영 도구를 완료한다.

## 랜덤 거점·영구 정찰 정보·온라인 단일 월드 보정 (2026-08-24)

### 거점 배치

- `battleMaps.ts`의 `spawnPairs`는 맵 공용 대칭 후보쌍이다. `resolveBattleSpawns(map, seed)`가 후보쌍과 청/적 방향을 한 번 결정한다.
- 컴퓨터 대전은 `createComputerMatch`가 만든 경기 시드를, 온라인은 Durable Object 방의 `seed`를 사용한다. 재대전은 방 시드를 새로 만들고 모든 참가자가 그 값을 다시 사용한다.
- 온라인 `MatchConfig`에는 방에서 받은 실제 로컬 진영인 `canonicalLocalTeam`을 보존한다. 런타임의 `blue=내 편`, `red=상대 편` 전투 의미는 유지하되, 로컬 거점은 실제 방 진영의 공용 좌표를 사용한다.
- 온라인 이동·영웅 스냅샷 좌표에는 시점별 180도 변환을 적용하지 않는다. 코어 HP만 방장 기준 청/적 값을 로컬 아군/적군 의미로 매핑한다.

### 컴퓨터 AI

- 팀별 `enemyCoreIntel`은 최초 시야 발견 후 경기 종료까지 유지한다. 현재 정찰 유닛이 죽거나 코어에서 멀어져도 정보를 잊지 않는다.
- 탐색 구역은 현재 맵의 모든 거점 후보와 전술 앵커를 중복 제거해 만든다. 유닛 ID와 탐색 단계로 분산하고, 이미 도착한 구역은 팀 단위 방문 집합에 기록해 같은 구역 반복을 줄인다.
- 무노선 진군대의 목표 우선순위는 `근거리 교전/공유 위협 → 지정 A/B → 발견한 적 코어 → 미방문 후보 탐색`이다. 발견 뒤 새 웨이브도 같은 팀 정보를 즉시 사용한다.
- 지원·포병 영웅의 전선 위치는 `전열 진군대와 자기 코어의 중간점`이 아니라 전열에서 자기 코어 방향 2~3칸 뒤의 열린 엄호 위치로 계산한다.
- 적 코어를 안 상태에서는 전장 어디의 설치물이든 선제 목표로 삼지 않는다. 인접 공격, 사선 공격, 실제 경로 차단 공성만 수행하고 이후 코어 공세를 재개한다.

### 온라인 동기화

- 방장 스냅샷은 기존 코어·영웅에 더해 웨이브, 진군대, 설치물과 변경된 지형 타일을 포함한다. 비방장 클라이언트는 공용 진영을 로컬 팀 의미로만 변환하고 좌표는 그대로 적용한다.
- 온라인 진군대는 `공용 진영 + 웨이브 + 슬롯` 동기화 ID를 사용한다. 비방장은 누락 개체를 생성하고 방장 스냅샷에 없는 개체를 정리한다.
- 설치물은 공용 진영·종류·좌표로 대조한다. 건설과 메우기는 명령으로 중계하고 방장 스냅샷으로 최종 보정한다.
- A/B 명령은 영웅 이동 명령과 동일한 공용 좌표를 사용한다. 상대 팀 노선은 화면에 표시하지 않지만 해당 팀 진군대 런타임에는 적용한다.
- 이 구조는 현재 제출판의 `명령 중계 + 방장 권위 스냅샷` 범위 안에서 상태 불일치를 줄이는 보정이다. 공개 경쟁 서비스의 완전 서버 권위 시뮬레이션을 대체하지 않는다.

### 회귀 테스트

- 여러 시드가 모든 후보쌍과 진영 교환을 재현하며 두 거점이 겹치지 않는지 검사한다.
- 온라인 청팀·적팀 클라이언트가 같은 시드에서 같은 두 공용 좌표를 사용하고, 로컬 아군/적군 의미만 반대인지 검사한다.
- 코어 발견 정보가 정찰병 제거 뒤에도 유지되고 다음 웨이브가 코어 공세를 선택하는지 검사한다.
- 온라인 타입과 런타임 연결에서 진군대·설치물·지형·A/B·건설·메우기 동기화 필드가 누락되지 않는지 검사한다.

## 무지시 자율 전선·교전 유지 보정 (2026-08-24)

### 진군대 열린 전선 목표

- A/B 노선이 없는 대전 진군대의 장기 목표는 `발견 코어 → 미방문 정찰 구역` 순서로 정한다.
- 장기 목표까지 현재 열린 길이 없으면 현재 연결 컴포넌트를 BFS로 훑고, 장기 목표와의 휴리스틱 거리가 가장 짧은 열린 셀을 `reachable frontier`로 사용한다.
- 직접 연결되면 목표까지 그대로 이동하고, 끊겨 있으면 열린 전선 끝에서 대기한다. 영웅 굴착이나 지형 파괴로 연결 컴포넌트가 바뀌면 매 행동 주기 다시 계산한다.
- 대전 무지시 진군대는 무경로 5초 회수 대상에서 제외한다. 캠페인 장별 회수·경비 정책과 사용자가 지정한 A/B 후퇴 정책은 그대로 유지한다.
- 한 정찰 목표의 열린 frontier에 도달한 진군대는 5.2초 동안 영웅의 합류·굴착을 기다린 뒤 다음 미방문 구역을 선택한다. 매 행동마다 목표를 바꾸며 영웅을 흔들지 않는다.

### 대전 영웅 표적과 전선 합류

- 일반 대전 영웅의 신규 교전 반경은 영웅 시야 능력치에 여유 5칸을 더하되 최소 12칸으로 사용한다. 코어 방어 표적과 팀 공유 공격자는 이 제한보다 우선한다.
- `aiTargetId`로 한 번 고정한 표적은 살아 있고 활성 상태이며 실제 공격 위치까지 경로가 28칸 이내면 신규 교전 반경 밖에서도 유지한다.
- 보이는 표적의 공격 위치까지 열린 경로가 없을 때 표적을 제거하지 않는다. 표적 방향의 다음 칸이 파괴 가능하면 기본 굴착/굴착 기술을 사용하고, 영구 장애물·아군 점유이면 다른 열린 인접 칸을 선택한다.
- 코어 미발견 상태의 영웅은 가장 멀리 전진한 자기 진군대의 `aiSearchGoal`을 공유한다. 진군대가 없을 때만 독립 정찰 구역을 고른다.
- 지원·포병은 공유 정찰 축 또는 코어 공세 축에서 전열 2~3칸 뒤를 유지하고, 표적을 획득하면 역할 사거리의 빈 공격 칸까지 접근한다.
- 컴퓨터 대전 시작 36초 뒤에도 코어 지식이 없으면 `triangulated intel`을 양 팀에 1회 부여한다. 이는 무작위 순간이동이 아니라 기존 목표를 코어 좌표로 바꾸는 처리이며, 온라인·캠페인에는 적용하지 않는다.

### 테스트 경계

- 막힌 장기 목표를 받은 진군대가 현재 열린 컴포넌트의 가장 가까운 전선 끝을 선택하는지 검사한다.
- 목표가 우회로로 연결된 경우 직선 벽 앞이 아니라 실제 최단 열린 경로를 선택하는지 검사한다.
- AI 영웅이 시야권 적을 획득하고, 짧은 시야 경계를 벗어나도 28칸 이내 도달 가능 표적을 유지하며, 파괴 가능한 벽 앞에서 대기로 고정되지 않는지 검사한다.

## 온라인 로컬 예측·이탈 종료·시각 준비 보정 (2026-08-25)

- 비방장 클라이언트가 스냅샷을 적용할 때 `state.playerId === localPlayerId`인 영웅의 위치·방향은 덮어쓰지 않는다. HP·최대 HP·생존 상태는 방장 권위를 적용한다.
- 상대 영웅과 진군대의 새 스냅샷 좌표는 500ms 표시 보간의 도착점으로 사용한다. 논리 상태는 즉시 갱신하되 렌더 좌표가 이전 스냅샷에서 새 좌표까지 이어져 보이게 한다.
- 진행 중 `leave` 요청 또는 10초 초과 연결 단절을 발견하면 방 상태를 `finished`로 바꾸고 이탈자 반대 팀을 승자로 기록한다. `aiControlled` 인계로 진행 중 경기를 유지하지 않는다.
- 첫 화면으로 나가는 명시적 조작은 전투 화면을 닫기 전에 `leave`를 전송한다. 탭 종료처럼 요청이 도달하지 않는 경우에는 남은 참가자의 폴링이 연결 제한 시간을 판정한다.
- 컴퓨터 대전과 온라인 전투 진입은 `preloadRuntimeVisuals` 완료 뒤에만 `play` 화면을 연다. 양쪽 클라이언트가 상대 영웅 공용 시트를 준비한 상태에서 첫 전투 프레임을 그린다.
- BGM v3는 사인 기반 패드·감쇠 피아노·현 플럭·브러시 노이즈와 잔향을 합성한다. 메뉴 트랙은 타악기를 제외하고 목표 볼륨을 전투보다 낮게 사용하며, 전투 트랙도 saw/square 리드 반복을 사용하지 않는다.

## 탭별 방 인증·영웅 편성 표현 보정 (2026-08-25)

- 온라인 `RoomClientIdentity`는 방 코드별 `sessionStorage`에 저장한다. 캠페인 진행처럼 탭 사이에 공유해야 하는 정보가 아니므로 `localStorage`를 사용하지 않는다.
- 새 참가 요청은 현재 탭에 저장된 같은 방·같은 호출명의 토큰이 있을 때만 재접속 토큰을 보낸다. 다른 탭의 방장 토큰이 참가 요청에 섞이지 않아 Durable Object가 새 B TEAM 참가자를 정상 생성한다.
- `HeroKitIcon`은 `heroKits.ts`의 각 슬롯 `mode`, 영웅 `color/accent`, 실제 `caption`을 사용한다. 모드는 근접·원거리·범위·지원·이동·제어·굴착 문양으로 묶되 접근성 이름에는 원래 행동 설명을 보존한다.
- 휴먼 편성 초상은 스프라이트 첫 셀의 시각 중심을 기준으로 유승천과 김씨만 5px 왼쪽 보정한다. 전투 프레임 좌표에는 영향을 주지 않는다.
- 자동 검증은 방 참가 코드가 탭별 저장소를 사용하는지, 공통 기술 아이콘 반복이 제거됐는지 확인한다. 수동 검증은 같은 브라우저 두 탭·같은 기본 호출명으로 A/B 슬롯, 준비, 시작, 양쪽 전투 진입을 확인한다.

## 전선 결속·친선전 전송 주기 보정 (2026-08-25)

- 무지시 진군대의 탐색 인덱스는 개체 ID가 아니라 같은 4인 출전대의 cohort를 사용한다. 출전대는 하나의 장기 전선 목표를 공유하고, 병과별 산개는 다음 칸 점수에서만 유지한다.
- 노선이 없는 진군대의 도달 가능 적 감지는 8칸으로 넓힌다. `aiTargetId`에 4.2초 표적 기억을 두고 표적 사망·경로 단절·기억 만료 전에는 다른 탐색 구역으로 바꾸지 않는다.
- 로비/결과의 상태 확인은 700ms, 실제 전투는 250ms를 사용한다. `setInterval` 중첩 호출 대신 응답이 끝난 뒤 다음 요청을 예약하는 순차 폴링을 사용한다.
- 방장 스냅샷은 250ms, 원격 영웅·진군대 렌더 보간은 300ms를 사용한다. 로컬 플레이어 위치 예측 경계는 유지한다.
- 방 응답은 `revision`이 현재 화면 상태보다 크거나 같을 때만 적용한다. 준비·시작·이탈과 전투 폴링 응답이 엇갈려 과거 상태로 되감기지 않게 한다.
- 이 조정은 현재 HTTP + Durable Object 친선전의 체감 개선이다. 상용 경쟁전의 WebSocket·서버 권위 고정 tick 이전을 대체하지 않는다.

## 다수 진군대 교전 슬롯 보정 — 2026-08-25

- 같은 표적을 쫓는 진군대는 `targetId:x,y` 공격 슬롯을 2.2초 동안 기억한다. 현재 프레임 예약과 다른 아군의 유효 기억 슬롯을 함께 검사한다.
- 슬롯 점수는 `예약/점유 페널티 → 실제 경로 길이 → 주변 아군 혼잡 → 역할별 희망 사거리 → 유닛별 안정 편향` 순으로 구성한다.
- 점유 때문에 최단거리 감소 칸이 모두 막힌 경우 420ms 뒤 같은 거리 또는 한 칸 우회까지 허용한다. 유닛 ID 기반 안정 편향으로 매 프레임 위·아래를 왕복하지 않는다.
- 방장 권위 온라인 스냅샷에는 최종 위치와 LV.1~5만 전송한다. 포위 슬롯은 동일 지형·유닛 상태에서 호스트가 계산하며 비방장 화면은 위치 보간 결과를 사용한다.

## WebSocket 방 전송·전술지원·팀 연구 구현 기준 — 2026-08-25

- 방 생성과 최초 참가만 HTTP를 사용한다. 참가 뒤 로비 상태, 준비, 시작, 전투 명령, 방장 스냅샷, 종료와 재대전은 `/api/rooms/:code/socket` WebSocket으로 교환한다.
- `RoomHub`는 Cloudflare Durable Object WebSocket Hibernation API의 `acceptWebSocket`, `webSocketMessage`, `webSocketClose`를 사용한다. 연결 첨부정보에는 `playerId`와 인증 토큰을 직렬화해 휴면 복귀 뒤에도 참가자를 식별한다.
- 서버 메시지는 현재 공개 방 전체를 담은 revision 기반 `room` 봉투다. 클라이언트는 더 최신 revision만 적용하므로 재접속·HTTP 폴백 응답이 현재 상태를 되감지 않는다.
- 브라우저는 연결 종료 시 0.6초부터 최대 5초까지 지수형 재접속을 시도하고 주기적 heartbeat를 보낸다. 명시적 `leave`는 즉시 경기 종료, 예기치 않은 단절은 Durable Object alarm의 유예시간 뒤 `disconnect` 종료로 판정한다.
- 전투 판정은 이번 제출 단계에서 계속 방장 권위다. WebSocket은 250ms HTTP 폴링을 없애 지연과 중복 요청을 줄이는 전송 개선이며, 공개 경쟁전 전에는 고정 tick 서버 권위 시뮬레이션으로 별도 이전한다.
- 온라인 스냅샷은 양 팀 진군대 레벨과 양 팀 크레딧을 포함한다. 연구·전술지원 명령은 참가자 팀으로 검증하고 방장 런타임에서 같은 비용과 재사용 대기시간을 적용한다.
- 전술지원 규격은 `game/tacticalSupport.ts`의 종족별 정의를 단일 기준으로 사용한다. 즉시 강화와 지역 조준을 분리하고 지역 피해는 유닛·설치물에만 적용해 코어 판정을 우회하지 않는다.
- 진군대 연구 규격은 `game/minionResearch.ts`의 비용·레벨 배율을 단일 기준으로 사용한다. 웨이브 자동 레벨은 팀별 최소 보장으로 적용한다.
- `tacticalBuffVisual(faction, role)`은 방어·공세 버프의 주 광원색, 보조 입자색과 상태 기호를 반환한다. 렌더러는 `tacticalStates[team].defenseUntil/offenseUntil`을 단일 시간 기준으로 검사하고 진군대에만 몸체 방사광·발밑 이중 링·회전 입자·방어/공세 배지를 그린다.
- 버프 광원은 스프라이트 뒤가 아니라 화면 합성 `screen` 패스로 몸체 위에도 약하게 얹어 실제 적용 대상을 읽을 수 있게 한다. 체력 바와 레벨 표기는 광원 뒤에 다시 그려 가독성을 보존한다.
- 도움말의 전술지원 카드는 정적 규칙을 중복 하드코딩하지 않고 실제 비용·지원명과 동일한 사용자 문구를 사용한다. 세 역할, 공용 재사용, 지역 조준 제한, 종족별 광원 의미와 팀 연구를 한 카드에서 설명한다.

## 같이하기 전투 실시간 경량 전송 — 2026-08-26

- WebSocket 전투 중 `command`는 Durable Object 전체 방 저장과 `room` 전체 방송을 거치지 않는다. 메모리의 순번 큐에 반영한 뒤 권한상 볼 수 있는 수신자에게 `{ type: "command", command, commandSequence }`만 즉시 중계한다.
- 방장 `snapshot`은 복구를 위해 Durable Object에 저장하되, 소켓에는 공개 방·플레이어·명령 이력을 중복하지 않고 `{ type: "snapshot", snapshot, commandSequence }`만 전달한다. 로비·준비·시작·종료·재대전은 기존 revision 기반 `room` 봉투를 유지한다.
- Durable Object는 활성 인스턴스 안에서 방 상태를 캐시한다. 저장하지 않은 명령 직후 다음 메시지가 과거 storage 값을 다시 읽어 명령 큐를 잃지 않게 하며, 다음 250ms 방장 스냅샷이 처리 순번과 함께 복구 상태를 영속화한다.
- 비밀 굴착전의 명령 공개 정책은 기존과 같다. 방장은 모든 참가자 명령을 받고, 비방장은 공개 전선전이면 허용된 명령을, 비밀 굴착전이면 자기 팀 명령만 받는다. 발신자에게 자기 명령을 되돌려 보내지 않는다.
- 클라이언트는 경량 명령을 전투 inbox ref에, 경량 스냅샷을 권위 snapshot ref에 직접 넣는다. 250ms 전투 동기화마다 React 방 상태를 갱신하지 않아 HUD 전체 재조정과 불필요한 렌더를 피한다.
- 키보드 이동 반복 명령은 최대 10Hz로 제한한다. 로컬 이동 프레임은 그대로 유지하고, 원격 권위 목표 갱신에 필요한 빈도만 전송해 운영체제 키 반복률에 따른 메시지 폭증을 막는다.
- 온라인 `ESC` 메뉴는 로컬 입력 차단 상태와 전투 시뮬레이션 정지 상태를 분리한다. 메뉴가 열려도 권위 전투와 스냅샷 처리는 계속되며, 키보드·모바일 이동 명령만 해제한다.
