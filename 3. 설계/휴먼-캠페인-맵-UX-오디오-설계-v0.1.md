### 3장 전투 개시 상태

- 시작 좌표는 중앙 2×2 영역을 둘러싼 유승천·김씨·안서나·강력한의 밀집 배치다.
- 최초 5.2초 동안 플레이어와 상대 AI를 잠그고 대사를 보여 준다.
- 대치 종료와 동시에 유승천의 이동·기본 공격·기술 입력을 해제하고, 김씨·안서나·강력한의 자유 난투 AI를 활성화한다.
- AI는 최근 자신을 공격한 상대에게 반격하고, 체력이 매우 낮은 상대를 마무리하며, 이미 여러 명이 노리는 대상에는 낮은 우선순위를 준다. 일반 표적은 2.2~4초마다 다시 평가한다.
- 세 동료 AI가 표적을 새로 평가할 때 플레이어 유승천을 선택하는 비율은 70%, 다른 동료를 선택하는 비율은 30%로 둔다. 각 비율 그룹 안에서는 거리·최근 공격자·낮은 체력·집중 공격 여부를 비교한다.
- 안서나는 4칸 거리를 유지하고 체력 72% 미만에서 치료를 우선한다. 김씨는 근접 추격과 주변 2명 이상일 때 전기장을 우선한다. 강력한은 저체력에서 방어 강화, 중거리에서 뚜껑 투척, 근거리에서 밀치기를 우선한다.
- 3장 참가자 체력은 350~480으로 높이고 참가자끼리 주고받는 피해를 기본값의 62%로 줄여 대련 시간이 충분히 이어지게 한다.
- 체력 0은 사망이 아니라 기권·대련 이탈이며, 승리 뒤 네 사람의 관계가 더 단단해진다.

### 3장 이동·공격 시각 동기화

- 근접 판정은 4방향 타일 이동에서 대각선으로 맞닿은 상대도 교전할 수 있도록 체비쇼프 거리로 계산하고, 추격·거리 유지 판단은 실제 직선 거리를 사용한다.
- AI의 논리 타일은 즉시 갱신하되 화면 좌표는 약 0.3초간 부드럽게 보간한다. 밀치기에도 같은 보간을 적용해 순간이동처럼 보이지 않게 한다.
- 3장 동료의 몸체는 방향이 검증된 대기·이동 시트만 사용하고, 공격은 짧은 전진 동작과 별도의 방향성 효과로 표시한다. 서로 다른 크기의 기술 원본 셀을 몸체 프레임으로 직접 축소하지 않는다.
- 휴먼 로스터의 김씨·안서나·강력한 원본 측면 시트는 모두 오른쪽을 향한다. 좌우 반전은 이 원본 방향과 현재 공격 방향을 비교해 한 번만 적용한다. 분사·방패·전자레인지 계열 효과는 시전자에서 표적 쪽을 향하고, 회복·강화 효과만 시전자 중심의 대칭 효과를 사용한다.

## 2장 호송 상태 모델

- `ScientistUnit` 3명을 일반 전투 유닛과 분리한다: `escortPointIndex`, `hp`, `alive`, `destinationProgress`.
- 박사는 유승천 위치와 무관하게 사전에 정의한 협곡 경유점 배열을 순서대로 이동한다. 길이 막히면 같은 폭 안에서 우회하며, 경유점 1칸 이내에 진입하면 다음 지점으로 진행한다.
- 박사 중 한 명이라도 사망하면 즉시 패배하고, 세 명 모두가 평택 입구 반경에 진입해야 승리한다.
- 절벽 설치물은 굴착·이동 불가 고지 타일 위에 고정 배치하고 아래 협곡 통로의 박사를 우선 조준한다. 고지는 통로와 분리되어 적 지상 유닛이 내려오지 않으며, 플레이어는 원거리 기술로 포대를 제거하거나 몸으로 투사체를 끊어 호송대를 보호한다.
- 우측 종착 구조물은 적 코어가 아니라 휴먼 `평택거점(연구소)`로 표시한다. 박사가 입구 반경에 진입하면 생존 인원을 판정한다.

## 1장 정찰충 도입 상태 모델

- `campaignScout` 유닛을 서울 거점 전방 5칸에 배치한다.
- 0~1.4초는 거점을 바라보며 정지하고, 1.4~3.2초는 반대 방향으로 달아난 뒤 전장에서 제거한다.
- 정찰충이 도망가는 동안 유승천 대사와 1차 침입은 시작하지 않는다. 정찰 종료 뒤 두 대사를 순서대로 출력하고 약 8.5초 시점에 1차 침입을 시작한다.

## 가독성 규격

- 웹 UI 기본 글꼴: `system-ui, "Noto Sans KR", "Malgun Gothic", sans-serif`.
- 픽셀 표현은 Canvas의 캐릭터·지형에만 남기고 HUD, 메뉴, 버튼, 대사와 미션 설명에는 사용하지 않는다.
- 기본 본문 최소 12px, 조작/보조문구 최소 11px, HUD 핵심 수치·미션 목표 최소 14px.
- 어두운 패널 위 일반 글자는 명도 대비가 높은 `#f2eee3`, 보조문구는 `#c9c4b8` 이상을 사용한다. 7~8px 글자와 저대비 회색을 제거한다.

## 캠페인 승패 목표 인터페이스

- `game/campaignObjectives.ts`를 5개 장의 사용자 노출 승리·패배 문구와 진행 문자열의 단일 기준으로 사용한다. 전투 판정이 바뀌면 이 목록과 자동 테스트를 함께 수정한다.
- 브리핑의 `mission-conditions`는 승리·패배 조건을 두 열로 보여 주고, 작은 화면에서는 한 열로 재배치한다. 서사 설명이나 난이도 설명에 조건을 섞어 숨기지 않는다.
- 전투의 `mission-objective-card`는 Canvas 내부 좌상단 안전 영역에 HTML HUD로 겹친다. Canvas에 글자를 직접 그리지 않아 시스템 글꼴, 의미 구조와 키보드 초점을 유지한다.
- 카드에는 `campaignObjectiveProgress()`가 만든 현재 진행 한 줄을 항상 남긴다. 세부 승패 조건만 사용자가 접거나 펼칠 수 있으며 새 작전은 펼친 상태로 시작한다.
- HUD 스냅샷은 기존 약 120ms 주기에 `missionStage`, `missionSubjectsAlive`, `missionSubjectsCompleted`를 함께 갱신한다. 장별로 기존 `enemies`, `enemy`, `missionTime`과 조합해 별도 고빈도 React 렌더를 만들지 않는다.
- 접근성 이름은 브리핑 `작전 승패 조건`, 전투 카드 `현재 작전 승패 조건`, 토글 `작전 조건 접기/펼치기`로 고정한다. 상태색과 함께 `승리`·`패배` 텍스트를 반드시 표시한다.

### 현재 판정 정합성 보정

- 2장은 과거 설계의 `박사 1명 사망 즉시 실패/3명 전원 도착`이 아니라 현재 확정 규칙인 `박사 전원 사망 시 실패/1명 이상 도착 시 성공`을 안내한다.
- 3장은 과거 자유 난투·세 동료 기권이 아니라 현재 2대2 팀 전투의 `안서나·강력한 기권`을 안내한다.
- 5장은 두 전투실 정리 뒤 최종 천안 연결 지점에 접근해야 성공으로 판정한다.

## 배경음 구현 규격

- 외부 저작권 음원을 임의로 포함하지 않는다. 제출판은 브라우저 `AudioContext`로 생성하는 반복 앰비언트 레이어 또는 사용 승인된 오디오 에셋만 사용한다.
- 첫 사용자 입력 뒤 오디오를 시작한다. 브라우저 자동재생 제한을 준수한다.
- 공통 베이스: 낮은 드론 + 느린 금속성 펄스. 전투 중에는 타악/노이즈 레이어를 추가하며, 결과·일시정지 시 볼륨을 낮춘다.
- 장별 테마는 주파수·리듬 패턴만 바꿔 에셋 수를 과도하게 늘리지 않는다. 2장에는 행진 펄스, 3장에는 불협화음, 4장에는 군체성 리듬, 5장에는 붕괴 경고음을 사용한다.

## 작전 이미지·커서·모바일 가로 UI 보정

- 브리핑 이미지는 `campaignChapterInfo`의 `asset`과 `assetAlt`를 1~5장 모두 필수로 둔다. 1·3·4·5장은 승인된 프롤로그 v12 장면을 재사용하고 2장은 박사 전용 이미지를 유지한다.
- 공통 브리핑 상단은 이미지 설명 카드와 승패 조건 카드를 같은 폭·높이의 2열로 렌더링한다. 900px 이하에서는 한 열로 쌓고 2장 투명 인물 이미지만 `object-fit: contain`, 나머지는 `cover`를 사용한다.
- 커서는 32×32 SVG 세 종류를 사용한다. 메뉴 기본은 `cursor-drill`, 클릭 요소는 `cursor-action`, Canvas 전장은 중앙 핫스폿의 `cursor-target`이며 시스템 커서를 폴백으로 남긴다.
- 휴대폰 가로 높이 600px 이하에서는 기존 520px 최소 높이를 제거하고 헤더 46px, 조작 독 최대 82px, 나머지를 전장으로 배분한다. 안전 영역을 포함한 `viewport-fit=cover`를 선언한다.
- 조작 독 순서는 방향키, 기술, 생존/아이템, A/B 전략, 건설이다. 48×66px 방향 버튼과 68×66px 기술 버튼을 제공하며 가로 폭이 부족하면 독 내부만 수평 스크롤한다.
- 터치 장치 또는 960×600 이하 전투는 미니맵을 접힌 상태로 시작한다. 세로 화면에는 비차단 가로 전환 안내를 고정하고 `requestFullscreen` 뒤 지원 환경에서 `ScreenOrientation.lock("landscape")`를 시도한다. iOS처럼 잠금을 지원하지 않는 환경은 수동 회전으로 계속 플레이한다.
- 4장 동행 경로는 인접 대형 BFS를 우선하고, 대형 목적지 소진 시 반경 2칸, 플레이어가 지나간 열린 셀 방향 순으로 복구한다. 첫 걸음이 동적 점유로 막히면 360ms 뒤 현재 최단거리 +1 이내 옆칸을 선택해 정체를 벗어난다.

## 캠페인 지도·상세·시네마틱 최신 화면 기준

- 확정 공통 프롤로그 MP4는 캠페인 최초 진입의 독립 영상 화면과 작전지도의 `프롤로그 다시 보기`에서만 재생한다. 작전 상세는 `.chapter-screen.mission-brief`를 사용하고 작전지도와 동일한 `MenuSceneBackdrop`을 렌더하며 프롤로그 MP4를 상세 배경으로 자동재생하지 않는다.
- 지도는 `campaignChapterStatus()`의 완료·진입 가능·잠금 상태를 시각과 실제 버튼 활성 상태에 함께 반영한다. 순차 해금 계산은 `game/campaignProgress.ts`를 단일 기준으로 사용한다.
- 난이도 데이터는 `easy / hard` 두 키만 사용하며 hard는 과거 normal 보정값을 승계한다.
- 장별 MP4는 정적 배포 에셋으로 포함하고 `controls`, `playsInline`, 명시적 건너뛰기와 로드 오류 안내를 제공한다. 시네마틱 화면에서는 게임 메뉴 BGM을 중지한다.

## 캠페인 결과 재시작·브리핑 정렬·휴먼 프레임 보정

- 캠페인 결과 화면의 `다시 플레이`는 페이지를 새로고침하지 않고 현재 장·난이도의 전투 런타임을 새 실행 ID로 초기화한다. 이미 본 시네마틱은 재생하지 않으며 로드 실패 시 상세 화면에서 다시 시도할 수 있게 한다.
- 브리핑의 제목, 이미지·설명, 승패 조건, 난이도와 행동 버튼은 하나의 최대 1080px 콘텐츠 폭을 공유한다. 이미지 카드와 조건 카드의 바깥 테두리·높이를 맞추고 페이지 자체는 세로 스크롤을 허용한다.
- 안서나 측면 시트는 대기·이동 프레임의 원본 방향과 기본 공격 프레임의 원본 방향이 반대다. 프레임별 원본 방향표를 사용해 기본 공격 중에만 목표 반대편을 보는 현상을 막는다.
- 강력한 기본 공격은 셀 경계를 침범하는 원본 효과 프레임을 사용하지 않고 온전한 타격 프레임을 준비·적중 구간 모두에 고정한다.

## 작전 기록 데이터와 상세 화면 배치

- `campaignChapterInfo`는 장별 `story` 문자열 두 개를 필수로 가진다. 텍스트는 `휴먼-캠페인-5막-스토리-기획-v0.1.md`의 최신 확정안을 그대로 사용한다.
- `.mission-story-record`는 이미지·설명 카드 아래, 난이도 위의 공통 콘텐츠 폭에 배치한다. 작은 영문 라벨, `작전 기록` 제목과 두 문단으로 구성한다.
- 이야기는 시네마틱 자막이나 자동 진행 대사로 재사용하지 않는다. 사용자가 상세 화면을 읽을 때만 보이며 영상 스킵·재시청 상태와 무관하다.
