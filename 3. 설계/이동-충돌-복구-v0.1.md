# 플레이어 이동 충돌·복구 설계 v0.1

## 상태

- 분류: 확정 구현
- 대상: 마우스 목적지 이동, 단차 작업대와 영구 장애물 주변

## 문제

기존 플레이어 이동은 목적지까지의 직선 벡터만 사용했다. 영구 단차벽으로 둘러싸인 작업대 안에서 바깥을 클릭하면 경사로를 탐색하지 않고 벽을 계속 밀기 때문에, 열린 공간에 서 있어도 빠져나오지 못하는 것처럼 보였다. 지형 갱신이나 돌진 뒤 몸 반경이 벽에 일부 겹친 경우에는 모든 이동 후보가 거절될 수도 있었다.

## 해결 규칙

1. 직선 진행이 열려 있거나 바로 앞에 파괴 가능한 흙이 있으면 기존 360도 연속 이동·굴착을 유지한다.
2. 직선 진행이 영구 장애물에 막히면 현재 타일부터 목적지 또는 목적지 인접칸까지 열린 타일 BFS를 수행한다.
3. BFS는 상하좌우만 사용해 벽 모서리를 대각선으로 뚫지 않고, 첫 경유지 중심을 향한 연속 이동 벡터만 반환한다.
4. 현재 몸의 네 모서리가 지형에 박힌 비정상 상태라면 반경 4칸에서 가장 가까운 안전 타일 중심으로 자동 복구한다.
5. 자동 복구는 비정상 충돌 상태에서만 발동하며 정상적인 벽 넘기나 순간이동 수단으로 사용할 수 없다.

## 캐릭터 가독성

- 유승천의 발밑 광원 원칙을 나머지 플레이어 영웅과 아군·적군 AI 영웅에도 적용한다.
- 영웅별 기술 강조색으로 반경 29~31px의 약한 방사광을 먼저 그리고, 원본 프레임에는 밝기·채도·대비 보정과 2~5px 이내의 외곽광을 적용한다.
- 발밑 링은 아군 청록, 적군 적색으로 고정해 캐릭터 고유색이 달라도 팀을 즉시 구분한다. 진군대·박사·설치물에는 영웅 광원을 적용하지 않는다.
- 팀 표식·체력 바와 중복되지 않게 광원은 몸체 아래에 제한하고, 기술 이펙트보다 약한 세기로 유지한다.

## 제4장 동행 영웅 정체 복구

- 동행 영웅의 정체 여부는 화면상 직선거리나 현재 목표 보유 여부가 아니라 실제 논리 셀의 마지막 변경 시각으로 판단한다.
- 플레이어까지 실제 경로가 5칸 이상이고, 유효한 근접 전투가 아닌 상태에서 2.2초 동안 셀 진행이 없으면 지원·추격을 포기하고 강제 추종으로 전환한다.
- 강제 추종은 위치를 직접 재배치하지 않고 기존 열린 경로 이동과 보간을 사용한다. 플레이어 인접 칸에 실제 도착할 때까지 장거리 지원 표적 재획득을 잠근다.
- 경로가 단절됐으면 현재 연결 성분에서 플레이어와 가장 가까운 열린 경계까지 이동해 기다리고, 지형 변경으로 길이 이어지는 즉시 자연 추종을 계속한다.
- 강제 추종에서도 실제 셀이 10초 이상 멈추고, 플레이어까지 5칸 이상이며, 현재 다음 칸도 막힌 경우에만 예외 순간이동을 허용한다. 목적지는 플레이어와 연결된 반경 2칸의 빈칸으로 제한하고 전용 효과·안내로 일반 이동과 구분한다.
