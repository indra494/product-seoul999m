- 기존 메뉴 기반 다중 포인트 편집은 제거한다. 전투 중 반응성을 우선한다.
- 마우스 커서가 열린 탐사 타일을 가리킬 때 `Ctrl+1`은 A, `Ctrl+2`는 B 전략 지점을 갱신한다.
- 명령은 캡처 단계에서 일반 `1/2` 기술 입력보다 먼저 처리해 기술과 충돌하지 않는다.

## 데이터

- `MarchRoute`: `id(A|B)`, `color`, `points[최대 6]`, `revision`
- `MarchRoute.stance`: `assault|guard|capture`. 돌격은 5타일 내 적을 추격하며 적 거점까지 진군한다. 경계는 이동 경로를 이탈해 추격하지 않는다. 점령은 마지막 목표 지점 반경 5타일 안 적만 최대 6타일 거리에서 제한 추격한다.
- `Unit`: `routeId`, `routePointIndex`, `routeWaitMs`, `routeRetreating`, `formationSide`
- 아군 노선은 경기 로컬 상태로 유지한다. 적 AI는 내부 목표 노선을 사용하되 플레이어 화면에 표시하지 않는다.
- 네트워크 확장 시 전체 경로가 아니라 `route revision + point array` 명령만 동기화할 수 있게 구성한다.

## 경로 편집

1. 왼쪽 진군로 메뉴에서 A 또는 B를 선택한다.
2. 탐사된 열린 타일을 클릭하면 선택 노선 끝에 포인트를 추가한다.
3. 이미 선택한 마지막 포인트를 취소하거나 노선을 전체 초기화할 수 있다.
4. 경로 편집 중 일반 이동·공격·건설·매립 입력은 실행하지 않는다.
5. 각 구간은 열린 타일 BFS로 연결한다. 연결할 수 없는 구간은 붉은 단절선과 X로 표시한다.

## 분산 이동 점수

- 기본 경로는 목표 포인트까지의 열린 타일 최단거리다.
- 매 이동 시 기본 다음 칸과 그 좌우 측면 후보를 평가한다.
- 점수 구성:
  - 목표까지 거리 감소: 큰 가점
  - 역할별 편대 위치 일치: 가점
  - 주변 열린 칸 수: 가점
  - 현재 칸·다음 칸 주변 아군 수: 감점
  - 다른 아군이 이번 틱에 예약한 칸: 큰 감점
  - 사격병이 적에게 너무 가까워지는 이동: 감점
- 최단 경로에서 최대 1칸 우회까지만 허용해 AI가 목적지를 잊고 산개하지 않게 한다.

## 상태 전이

- `march`: 다음 경로 포인트로 이동
- `rally`: 마지막 포인트 반경에서 대기·근거리 자동전투
- `blocked`: 열린 경로가 없으면 현재 위치에서 전방 경로만 재탐색
- `recall`: 실제 전방 연결을 7초 이상 복구하지 못하면 거점 회수
- 교전과 아군 혼잡은 `blocked` 시간을 증가시키지 않는다.

## 구현 제약

- 영웅의 연속 360도 이동과 진군대의 타일 이동은 분리 유지한다.
- 진군대 최대 12명·56×36 맵이므로 매 이동 시 제한 BFS를 사용해도 브라우저 비용이 작다.
- 프레임마다 전체 유닛 경로를 계산하지 않고 각 유닛 행동 틱에만 재계산한다.
- 포인트와 노선은 미탐색 지역을 드러내지 않는다.
- 경로 탐색 함수는 다음 칸을 고르기만 하며 예약 상태를 변경하지 않는다. 실제 점유 검사에 성공해 이동을 확정하는 공용 이동 함수만 목적 칸을 예약한다. 같은 유닛이 탐색 단계에서 만든 예약에 스스로 막히는 이중 예약을 금지한다.
- 다음 칸 후보에서 아군·거점·설치물·다른 진군대가 예약한 칸은 통로 폭·밀집도·거리 점수보다 항상 큰 차단 감점을 받는다. 비어 있는 우회 칸이 하나라도 있으면 점유 칸을 선택하지 않는다.

## 테스트 범위

- A/B 빠른 지정, 상세 초안의 적용·초기화·취소와 내부 64개 안전 상한
- 1노선 4명, 2노선 2:2 웨이브 배분
- 집결점 대기와 주변 적 자동 공격
- 단절 3초 뒤 전방 재결합, 7초 장기 단절 시 거점 회수와 일시 혼잡 시 후퇴 금지
- 2칸 이상 열린 통로에서 병력이 여러 행·열로 분산되는지 확인
- 1칸 통로에서는 기존 병목·혼잡 굴착 규칙이 유지되는지 확인
- 미니맵 안개가 경로선 때문에 미탐색 지형을 노출하지 않는지 확인
- Ctrl+1/2 또는 상세 재지정 때 기존 아군이 현재 진행률 이후 셀에 합류하는지와 세 태세의 이동·추적 반경이 구분되는지 확인

## 2026-08-24 상호 회피 회랑 설계 v0.3

### 편집 우선순위

- `applyTeamRouteTarget(team, editedId, target)`는 반대 `RouteId`의 현재 계획 셀을 읽고, 반대 노선은 수정하지 않은 채 `editedId`만 다시 계획한다.
- 따라서 A→B에서는 B가 A를 피하고, A→B→A에서는 마지막 A가 B를 피한다. A/B 이름에 따른 고정 우선순위는 없다.
- `MarchRoute.points`는 사용자가 지정한 최종 좌표를 보존하고, `plannedCells`는 실제 진군 회랑 전체를 보존한다. `pathMode`는 `direct|flank|shared`, `overlapRatio`는 반대 노선과의 실제 중복률이다.

### 결정론적 분리 경로

1. 일반 BFS 최단 경로를 기준 길이로 계산한다.
2. 반대 노선의 정확한 셀에는 큰 비용, 1칸 인접 셀에는 작은 비용을 더한 가중 Dijkstra 경로를 계산한다.
3. 시작 4칸과 목표 2칸 반경은 불가피한 합류·진입 구간으로 보고 중복 비용에서 제외한다.
4. 가중 경로가 일반 최단 경로보다 중복을 줄이고 `최단 길이 × 1.85 + 6칸` 안이면 우회 후보로 채택한다.
5. 가중 후보를 쓰지 않아도 일반 최단 경로 자체가 반대 노선과 45% 이하만 겹치면 `flank`로 인정한다. 같은 길이거나 45%를 넘게 겹치면 `shared`로 표시한다.
- 네 방향 탐색 순서와 동점 규칙을 고정해 같은 지형·명령에서 컴퓨터 대전과 온라인 참가자가 같은 결과를 얻는다.

### 런타임 사용

- 진군대의 `routePointIndex`는 `plannedCells`를 순서대로 소비한다. 최종 좌표만 놓고 매 행동 틱 최단 경로를 새로 고르지 않는다.
- 안내 화살표도 같은 `plannedCells`를 그려 표시 경로와 실제 이동 경로를 일치시킨다.
- `flank`는 목표 표식에 `우회`, 단일 통로 폴백은 `공용 병목`을 표시한다.
- 돌격 분대가 마지막 계획 셀에 도달했고 상대 코어 좌표를 알고 있으면 목표를 코어로 넘긴다. 경계·점령은 기존 집결 행동을 유지한다.
- 컴퓨터 팀은 코어 발견 후 같은 코어를 목표로 A를 먼저 만들고 B를 A 회피 경로로 만든다. 영웅은 자기와 같은 노선의 선두 진군대를 엄호한다.
- 온라인은 기존 `route + target` 명령을 유지한다. 경로 계획 함수가 순수·결정론적이며 방장 지형 스냅샷을 공유하므로 별도 대용량 셀 배열 명령을 추가하지 않는다.

### 추가 테스트

- 두 개의 열린 회랑이 있는 맵에서 A와 B의 유효 구간이 서로 달라지는지 확인한다.
- A→B→A 재지정 시 B는 유지되고 새 A가 B와 다른 회랑을 선택하는지 확인한다.
- 단일 병목 맵에서는 명령이 실패하지 않고 `shared`로 폴백하는지 확인한다.
- 표시 `plannedCells`와 진군대가 소비하는 셀 배열이 같은지 확인한다.
- 돌격은 진입점 통과 후 코어로 진행하고 경계·점령은 집결점에 머무는지 확인한다.

## 2026-08-25 반대 측면·원거리 회랑 우선 설계 v0.4

- 반대 노선 셀에서 맨해튼 거리 0·1·2인 칸에 단계형 근접 비용을 적용한다. 단순 exact overlap 0인 평행 통로도 같은 길로 보이는 문제를 막는다.
- 시작→목표 벡터를 기준으로 반대 노선 유효 셀의 평균 외적 부호를 구한다. 부호가 명확하면 새 노선은 그 반대 반평면을 우선하고, 중앙선과 기존 노선 측면에는 추가 비용을 준다.
- 후보 채택은 중복률 감소뿐 아니라 반대 노선까지의 평균 이격 증가도 인정한다. 경로 길이가 최단의 2.35배+8칸 안이면 더 멀리 떨어진 회랑을 우선하고, 이 범위를 넘거나 대체 연결이 없을 때만 최단 공용 경로를 사용한다.
- 회귀 테스트는 `정확히 겹치지 않지만 같은 측면에 붙은 가까운 통로`와 `더 먼 반대 측면 통로`를 함께 제공하고 후자가 선택되는지 검사한다.

## 2026-08-25 강제 분리 후보 설계 v0.5

- 마지막 편집 노선은 먼저 반대 노선의 유효 셀과 인접 1칸을 통행 금지한 `hard flank` 후보를 찾는다. 시작·도착 주변의 불가피한 공용 셀만 금지에서 제외한다.
- hard flank가 연결되면 최단 경로보다 길어도 허용 가능한 상한 안에서 최우선 채택한다. 정확한 셀만 피한 가까운 평행 통로보다 반대 측면의 멀리 떨어진 연결로를 우선한다.
- hard flank가 없을 때만 기존 가중 경로를 사용하고, 가중 경로도 없을 때 일반 최단 경로를 `shared`로 사용한다. 통로가 하나뿐인 맵의 명령은 실패시키지 않는다.
- 실제 전투의 A/B 즉시 지정은 시작·도착 공용 반경을 각 1칸으로 줄이고, 일반 기본값보다 큰 이격 비용과 넓은 우회 길이 상한을 전달한다.
- `A 지정 → B 지정 → A 재지정`은 항상 현재 반대 노선의 `plannedCells`를 기준으로 마지막 A만 다시 계산한다.

## 2026-08-26 동일 목표 상·하 회랑과 혼잡 복구 v0.6

- A/B의 마지막 목표 좌표가 같으면 경로 탐색에 화면 기준 선호 방향을 전달한다. A는 기준축 위쪽, B는 아래쪽 후보를 먼저 탐색한다. 시작·도착 공용 반경 밖에서는 반대 선호 측면에 추가 비용을 준다.
- 선호 측면에 연결된 회랑이 없으면 반대편 우회로를 허용하고, 별도 회랑 자체가 없을 때만 `shared`로 폴백한다. 따라서 명령은 실패하지 않지만 실제로 존재하지 않는 아래 길을 거짓으로 표시하지 않는다.
- 컴퓨터 영웅도 배정된 `MarchRoute.plannedCells`와 `routePointIndex`를 소비한다. 노선 끝에 도달한 뒤에만 적 코어 공격 위치를 직접 탐색한다.
- `pathPlanToGoals`가 지형 경로는 찾았으나 다음 칸만 아군·예약에 막힌 상태는 `congested`로 취급한다. 이 경우 측면 양보와 재시도를 사용하고 `noPathMs`를 증가시키지 않는다.
- 태세 정책은 순수 판정으로 고정한다. 돌격만 코어까지 연장되고, 경계는 경로 이탈 추격 반경 0, 점령은 집결점 반경 5 안의 적만 최대 6칸 추격한다.

### 2026-08-26 검증 결과

- 동일 목적지의 B 하단 회랑, 영웅 경로 커서 진행, 돌격·경계·점령 정책과 혼잡 시 경로 보존을 자동 회귀 테스트로 고정했다.
- 프로덕션 빌드 포함 전체 자동 테스트 92/92, ESLint 오류 0건·기존 경고 12건을 통과했다. 실제 개방 전선전 2:2에서 적 영웅이 기지 앞까지 진입해 기술을 사용하고 웨이브 공세가 지속되는 것을 확인했다.

## 2026-08-26 전 모드 공통 빠른·상세 경로 편집 v0.7

### 입력과 초안

- `Ctrl+1 / Ctrl+2`는 기존처럼 커서 위치 하나를 최종점으로 삼아 자동 분리 경로를 즉시 확정한다.
- A/B 지휘 행의 `빠른 지정`은 다음 Canvas 터치·클릭 한 번을 같은 자동 경로 명령으로 처리한다.
- A/B 지휘 행의 `상세 수정`은 기존 `MarchRoute`를 직접 바꾸지 않고 별도 `RouteDraft`를 빈 점 배열로 시작한다.
- 상세 수정의 각 포인트는 탐사·통행·연결 검사를 통과해야 초안 끝에 추가한다. 마지막 포인트가 최종 목적지이고 이전 포인트는 경유점이다.
- 사용자에게 포인트 상한을 노출하지 않는다. 동일 좌표 중복은 무시하고, 저장·온라인 남용 방지를 위한 내부 안전 상한만 충분히 크게 둔다.
- `적용`은 초안 전체를 `MarchRoute.points`로 교체하고 `stitchRoutePoints`로 `plannedCells`를 다시 만든다. `초기화`는 초안만 비우고 `취소`는 초안을 폐기한다.
- ESC·우클릭·Enter는 상세 경로 조작에서 제거한다. 전용 화면 버튼만 사용한다.

### 이동 안정성

- 경로 수정 뒤 기존 진군대의 커서는 현재 커서보다 뒤로 낮아지지 않는다. 새 경로의 현재 인덱스 이후 후보 중 실제 도달 가능한 가장 가까운 셀로 재결합한다.
- 진군대가 혼잡 회피로 경로의 뒤쪽 셀을 건너뛰어 도착하면 `advanceRouteCursor`로 최대 10칸 앞의 도달 셀을 소비한다.
- 혼잡 양보는 목표 거리를 늘리는 후퇴 이동을 우선하지 않으며, 방금 떠난 셀로 즉시 역행하는 이동을 짧게 잠근다. 진짜 지형 단절이 아니면 이전 경유점이나 거점으로 후퇴하지 않고 현재 위치에서 재탐색한다.
- 비밀 굴착전 배분 변경은 `tunnelAllocations`만 갱신한다. 현재 출전 병력은 기존 노선과 커서를 유지하고 다음 웨이브의 `chooseSpawnRoute`부터 새 비율을 사용한다.
- 비밀 굴착 준비 중 확정한 사용자 A/B 경로는 침공 전환 때 자동 코어 경로로 덮어쓰지 않는다. 비어 있는 노선만 자동 보완한다.

### 온라인과 모바일

- 온라인 `route` 명령은 빠른 지정의 `x/y` 또는 상세 수정의 `points[]` 중 하나를 운반한다. Worker는 A/B 식별자, 좌표의 유한값과 내부 안전 상한을 검증한다.
- Pointer Event를 공용으로 사용한다. 상세 수정에서 짧은 탭은 포인트 추가, 임계 거리 이상의 드래그는 카메라 이동으로 구분한다.
- 모바일 전술 패널에도 A/B 빠른 지정·상세 수정 버튼을 동일하게 노출하고, 상세 수정 중 화면 고정 `적용 / 초기화 / 취소`를 최소 44px 터치 영역으로 제공한다.

### 검증

- 프로덕션 빌드와 전투·UI·온라인 회귀 테스트 93/93을 통과했다.
- 브라우저에서 비밀 굴착전 A/B 공통 패널, 상세 초안의 포인트 추가, 적용 비활성/활성 전환과 초안 초기화를 확인했다.

## 2026-08-26 압축 경로 지휘·AI 정체 복구 v0.8

### 지휘부와 입력

- 각 `route-command-row`는 클릭 가능한 단축 표식, 상세 `수정`, 모드가 허용하는 태세 버튼만 한 행에 배치한다. 별도의 `빠른 지정 / 상세 수정` 2버튼 행을 제거해 236px 지휘부 안에서 A/B 두 행을 유지한다.
- 표식 클릭은 `routeQuickAim`을 설정하고 다음 좌클릭·탭을 빠른 목적지로 사용한다. 키보드 `Ctrl+1 / Ctrl+2`는 기존 즉시 명령 경로를 변경하지 않는다.
- `routeEdit` 상태에서도 우클릭 `cameraDrag`를 시작할 수 있다. 우클릭 드래그는 `routeDraftPoints`, `routeDraftCells`, 확정 경로를 전혀 변경하지 않는다.

### 초안 렌더링

- 확정 `MarchRoute`와 `RouteDraft`를 한 객체로 치환해 그리지 않는다. 확정선은 낮은 알파로 별도 렌더링하고 초안은 `ALLY + routeDraftCells`를 굵은 점선으로 그린다.
- 사용자가 클릭한 `routeDraftPoints`에는 1부터 시작하는 순번 표식을 그리며 마지막 표식은 크기·색·`최종` 라벨로 강조한다. 미탐색 셀은 확정선과 초안선 모두 그리지 않는다.

### 이동 속도와 컴퓨터 영웅 복구

- 공용 이동 배율 `GLOBAL_UNIT_MOVEMENT_MULTIPLIER = 1.3`을 영웅 연속 이동, 타일형 진군대·호위 대상 이동, AI 영웅의 격자 행동 간격에 한 번씩 적용한다. 공격·기술 시간에는 적용하지 않는다.
- 컴퓨터 영웅이 목표를 가졌지만 `combatApproachPlan`이 공격 위치를 만들지 못한 경우 즉시 `wait-path`로 반환하지 않는다. 열린 네 방향 중 목표 거리와 혼잡도를 줄이는 복구 칸을 선택하고, 실패 시간 누적 뒤에는 고정된 표적을 해제해 장기 공세 경로를 다시 계산한다.
- 이동 성공 여부를 확인하지 않고 행동 대기만 거는 분기를 금지한다. 실패 시 짧은 재시도와 측면 탈출을 사용하고, 실제 이동 성공 때만 정체 시간을 초기화한다.

### 회귀 범위

- 236px A/B 지휘부에 두 행이 들어가며 뒤의 유틸리티·기술 바를 밀어내지 않는지 확인한다.
- 상세 수정 중 기존선과 굵은 초안선·순번 점이 동시에 구분되고 우클릭 드래그 뒤 포인트를 계속 추가할 수 있는지 확인한다.
- 적 영웅의 접근 경로가 아군 진군대 한 칸에 막힌 상황과 공격 위치를 못 찾는 상황에서 1초 안에 측면 이동 또는 표적 재탐색이 발생하는지 확인한다.
- 전체 이동 시간만 기존 대비 약 `1 / 1.3`으로 줄고 공격 간격·기술 재사용 값은 유지되는지 확인한다.

## 2026-08-26 단일 공세 태세·전 모드 웨이브 배분 v0.9

### 입력·HUD

- `route-command-row`는 A/B 표식 자체만 조작점으로 사용한다. 표식의 포인터 입력은 `beginRouteEdit(id)`로 상세 초안을 시작하고, 별도 `수정`과 태세 버튼은 렌더링하지 않는다.
- 키보드 캡처 단계의 `Ctrl+1 / Ctrl+2`는 기존 `setRouteTarget`을 유지해 커서 한 점으로 즉시 확정한다. 포인터 표식과 키보드 단축키의 역할을 코드 경로에서 분리한다.
- 캠페인·두 대전 규칙·온라인 모두 세 번째 행에 `50:50 / 75:25 / 25:75` 배분을 노출한다. 표시는 `균등 / A 집중 / B 집중`으로 통일한다.

### 진군 판정

- `MarchRoute`에서 런타임 `stance` 필드를 제거한다. 과거의 세 태세 유틸리티가 남아 있어도 실제 진군 판정은 `marchStanceBehavior("assault")`만 사용한다.
- 두 노선이 모두 활성화됐을 때 `chooseSpawnRoute`는 모드와 무관하게 팀의 배분 값으로 새 웨이브를 A/B에 배정한다. 기존 유닛의 `routeId`와 `routePointIndex`는 배분 변경으로 수정하지 않는다.
- 컴퓨터 팀 기본 배분은 A 집중을 유지하되, 실제 A/B 경로는 모두 상대 코어까지 공격하는 동일 공세 규칙을 따른다.

### 주변 기능

- 현재 시야 계산에 아군 코어 중심 고정 반경을 추가해 영웅 사망 후에도 코어 주변 포그를 완전히 제거한다.
- 건설 직접 선택은 `Digit5..Digit9`, 강화 `KeyU`, 철거 `KeyX`를 `processCommand(build:...)`로 연결해 메뉴 개폐 상태와 독립시킨다.
- 특성 창은 미선택 단계뿐 아니라 선택 완료 단계도 탭으로 열 수 있다. 완료 단계는 후보 선택 버튼 대신 확정 특성의 이름·설명 카드만 렌더링한다.
